## پرامپت کپی برای سازنده

```text
تو Agent توسعهٔ GYM CONTROL هستی. docs را خودت پیدا کن (business-rules، getting-started، testing، roadmap-status، project-rules، security). فیچر خارج از این برش نساز. HTML ریشه (ماکت Pages) را دست نزن — فقط frontend/ + backend/.

## زمینه
صاحب پروژه دادهٔ seed را پاک کرده و می‌خواهد باشگاه را از صفر با دادهٔ واقعی خودش بالا بیاورد.
طبق business-rules §۲: «مدیر حساب منشی و مربی را می‌سازد. اولین مدیر روی سرور ساخته می‌شود.»
طبق prototype: مدیریت طرح‌های اشتراک (افزودن/ویرایش) لازم است.
الان در کد:
- ساخت User (منشی/مربی/مدیر) از UI یا API عمومی نیست؛ فقط seed یا تغییر رمز توسط مدیر.
- طرح‌ها فقط GET `/api/v1/membership-plans`؛ POST/PATCH/غیرفعال‌سازی نیست؛ UI ساخت طرح نیست.
- عضو جدید از UI منشی/مدیر موجود است.

## هدف برش (یک vertical slice)

### ۱) Bootstrap اولین مدیر (سرور / CLI)
- وقتی هیچ User با role=manager وجود ندارد، یک دستور امن لوکال برای ساخت اولین مدیر (مثلاً `python -m app.db.bootstrap_manager` با آرگومان موبایل/نام/رمز).
- اگر مدیر از قبل هست → خطا/رد واضح؛ ساخت مدیر دوم از این CLI ممنوع مگر صریح اجازهٔ env/فلگ (ترجیح: فقط وقتی صفر مدیر).
- هرگز رمز را در گیت نگذار؛ فقط آرگومان/env موقت.
- در getting-started یک بخش کوتاه «شروع بدون seed» بنویس.

### ۲) مدیریت کارکنان توسط مدیر (API + UI)
- فقط role=manager.
- لیست کارکنان (موبایل، نام، نقش، فعال/غیرفعال).
- ساخت منشی و مربی: موبایل یکتا، نام، رمز (≥۸)، نقش receptionist|trainer.
- مدیر نمی‌تواند از UI نقش manager جدید بسازد مگر تصمیم صریح در docs (پیش‌فرض: نه — فقط bootstrap/CLI برای اولین مدیر).
- تغییر رمز کارکنان (قبلاً تا حدی هست؛ یکپارچه کن).
- غیرفعال‌سازی حساب (حذف دائمی ممنوع؛ مشابه عضو).
- UI در پنل مدیر (مثلاً `#staff`) با Ocean Dark MPA موجود؛ منشی این بخش را نبیند؛ API هم ۴۰۳.
- audit برای ساخت/تغییر نقش/رمز/غیرفعال.

### ۳) CRUD طرح عضویت (API + UI مدیر)
- فیلدها طبق مدل: name، description اختیاری، duration_days و/یا session_count (حداقل یکی)، base_price_toman ≥0، includes_locker، is_active.
- POST ساخت، PATCH ویرایش (قیمت جدید سوابق membership گذشته را عوض نکند — فقط قیمت پایهٔ طرح برای تمدیدهای بعدی).
- غیرفعال‌سازی (is_active=false) به‌جای حذف؛ طرح غیرفعال در select تمدید نیاید.
- UI مدیر: `#plans` یا داخل تنظیمات/مالی — فرم ساخت + لیست؛ برچسب «شامل کمد» واضح.
- منشی: فقط خواندن طرح‌های فعال (مثل الان) کافی است مگر docs بگوید بیشتر.
- مهمان یک‌روزه: اگر مهمان روزانه به طرح با نام مشخص وابسته است، در UI/docs بگو یک طرح ۱روزه «مهمان…» بسازند یا seed حداقلی اختیاری جدا از fake members.

## خارج از محدوده
- seed کامل با علی/سارا و دادهٔ نمایشی را برنگردان مگر تست‌ها نیاز داشته باشند (تست‌ها fixture خودشان).
- درگاه/پیامک/PWA/OTP.
- اجارهٔ جدا کمد.
- HTML ریشه.

## تست و تحویل
- pytest برای: bootstrap فقط وقتی صفر مدیر؛ مدیر منشی می‌سازد؛ منشی نمی‌تواند staff بسازد؛ CRUD طرح + قیمت جدید membership قدیم را عوض نمی‌کند؛ غیرفعال از لیست فعال حذف می‌شود.
- vitest برای UI helpers یا mount پنل اگر منطقی است.
- pytest و npm test سبز قبل از commit/push.
- به صاحب بگو: OK کامل یا ناقص + چطور بدون seed اولین مدیر و یک طرح بسازد (۳–۵ قدم).
```
