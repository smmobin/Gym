## هدف
یک **پنل وب مخصوص سازنده** بساز که ریزترین لاگ‌های فایل (`access` / `app` / `error` / `sensitive`) را کامل و قابل‌جستجو نشان دهد.
پنل مدیر `/manager/#activity` را دست نزن از نظر محدوده — همان خلاصهٔ فعالیت باشگاه بماند (ورود/خروج، پول/طرح/تنظیمات، خلاصهٔ خطا). لاگ کامل فقط در پنل سازنده.

## الان چیست / نیست
- هست: فایل‌ها در `backend/logs/` + UI مدیر خلاصه `#activity`
- نیست: هیچ URL وب برای دیدن کل لاگ فایل‌ها

## طراحی امنیتی (اجباری — بدون این نساز)
1. صفحه و API فقط وقتی روشن‌اند که در env:
   - `DEV_LOG_VIEWER=true` (یا معادل)
   - و `DEV_LOG_VIEWER_TOKEN` یک رشتهٔ بلند تصادفی (≥۲۴ کاراکتر) ست شده باشد
2. در `APP_ENV=production` / production-like: پیش‌فرض **خاموش مطلق**؛ حتی اگر کسی اشتباه flag بگذارد، یا فقط با توکن خیلی قوی + هشدار — ترجیح صاحب: در production کلاً ۴۰۴/۴۰۳ و در docs بگو روی سرور واقعی از فایل/SSH استفاده شود مگر صاحب صریح بخواهد.
3. هر درخواست API بیننده: هدر `X-Dev-Log-Token: <token>` یا ورود یک‌بار با همان توکن در UI (sessionStorage کوتاه؛ توکن را در گیت/seed نگذار).
4. بدون توکن درست → ۴۰۱/۴۰۳؛ بدون flag → ۴۰۴ (وجود endpoint لو نرود تا حد ممکن).
5. هرگز محتویات لاگ را به نقش manager/receptionist عادی از مسیر `#activity` وصل نکن. این پنل جداست — ترجیحاً مسیر جدا مثل `/dev-logs/` (نه زیر منوی مدیر باشگاه به‌عنوان آیتم دائمی برای منشی).
6. توکن و `.env` commit نشوند؛ فقط `.env.example` با کلید خالی و توضیح.

## قابلیت UI سازنده (شیک، Ocean Dark، RTL)
مسیر پیشنهادی: `http://127.0.0.1:5173/dev-logs/` (یا mount از dist وقتی SERVE_FRONTEND).
- انتخاب فایل: access / app / error / sensitive
- نمایش دم فایل (tail) با صفحه‌بندی یا «بارگذاری خطوط بیشتر»
- جستجو روی متن، فیلتر سطح (INFO/ERROR)، فیلتر `rid=` / request_id
- رفرش دستی + گزینهٔ auto-refresh ملایم (مثلاً هر ۵–۱۰ثانیه، قابل خاموش)
- لینک/کپی request_id
- خروجی دانلود همان فایل یا بازهٔ خطوط دیده‌شده به‌صورت `.log`
- ظاهر حرفه‌ای ترمینال‌مانند خوانا (فونت mono برای خطوط لاگ OK) ولی در پوستهٔ Ocean Dark پروژه
- اگر viewer خاموش است: صفحهٔ ساده «بیننده خاموش است — DEV_LOG_VIEWER را در .env بگذار»

## API پیشنهادی (تحت /api/v1 یا مسیر جدا؛ سبک پروژه را حفظ کن)
- `GET .../dev/logs/files` — لیست فایل‌های مجاز داخل LOG_DIR فقط (نام، اندازه، mtime) — با توکن
- `GET .../dev/logs/read?file=access&offset=&limit=&q=` — خواندن امن؛ path traversal ممنوع (فقط نام‌های allowlist)
- `GET .../dev/logs/download?file=access` — attachment `.log`
حداکثر limit معقول (مثلاً ۲۰۰۰ خط در هر درخواست) تا حافظه نترکد.
