تو Agent توسعهٔ پروژهٔ GYM CONTROL هستی. docs را خودت پیدا و بخوان. لیست URL از صاحب نخواه.

## هدف
حذف toastهای «لاگ شمارش / بارگذاری موفق» که بعد از لود لیست یا auto-refresh به کاربر نشان داده می‌شوند. صاحب پروژه صریحاً گفته این‌ها نباید به‌صورت نوتیف شناور بیایند.

## زمینه
`setStatus` در `frontend/assets/js/ui.js` همهٔ پیام‌ها را به toast شناور تبدیل می‌کند. چند صفحه بعد از هر لود (و گاهی حتی در `silent` مربوط به `createAutoRefresh` هر ~۱۵ثانیه) پیام سبز مثل «N عضو / N نفر / N طرح» می‌زنند. این لاگ داخلی است، نه بازخورد اکشن کاربر.

الگوی درست همین الان در `classes.js` هست: بعد از لود موفق، toast شمارش نزن؛ در silent هیچ status نزن؛ فقط خطا toast خطا بماند؛ لود دستی در صورت نیاز loading کوتاه و بعد پاک‌سازی با `setStatus(status, '')`.

## داخل محدوده — این toastها را حذف کن (کدهای A1–A8)

در لود موفق لیست/صفحه، این پیام‌های ok را نشان نده (نه دستی، نه silent):

| کد | فایل تقریبی | متن تقریبی |
|----|-------------|------------|
| A1 | `frontend/assets/js/members.js` | `${n} عضو` |
| A2 | `frontend/assets/js/staff.js` | `${n} نفر` |
| A3 | `frontend/assets/js/plans.js` | `${n} طرح` |
| A4 | `frontend/assets/js/lockers.js` | `${n} کمد` (و هر toast شمارش کمد بعد از لود لیست؛ ساخت/واگذاری جداست) |
| A5 | `frontend/assets/js/desk-dashboard.js` | «خلاصهٔ امروز به‌روز شد.» |
| A6 | `frontend/assets/js/panels/trainer.js` | `${n} شاگرد` |
| A7 | `frontend/assets/js/trial.js` (صف میز، نه فرم عمومی) | `${n} درخواست` بعد از لود لیست |
| A8 | `frontend/assets/js/settings.js` | «بارگذاری شد.» |

قواعد پیاده‌سازی:
1. در مسیر `load` / `loadToday`-مانند: اگر `silent` بود → هیچ `setStatus` موفقیت/loading نزن (مگر پاک‌کردن loading قبلی لازم باشد).
2. لود دستی اول صفحه: می‌توانی `loading` کوتاه بگذاری؛ بعد از موفقیت `setStatus(status, '')` یا معادل clear — **بدون** پیام ok شمارش/«به‌روز شد»/«بارگذاری شد».
3. خطای لود همچنان toast `error` مجاز است (ترجیحاً در silent هم اگر قبلاً الگوی پروژه خطا نشان می‌دهد، همان را حفظ کن مگر نویز شدید بسازد — اولویت با حذف okهای شمارش است).
4. toastهای **بعد از اکشن کاربر** دست نزن: ثبت عضو، ذخیره، پرداخت، رزرو، واگذاری کمد، و غیره (گروه C در ممیزی PM).
5. اعلان‌های صندوقی میز (زنگ) و ورزشکار (`#notif`) را در این برش تغییر نده (گروه E/F).
6. اگر تستی انتظار «N عضو» / «N طرح» / «بارگذاری شد» در toast دارد، تست را با رفتار جدید هم‌خوان کن و حداقل یک تست رگرسیون بگذار که بعد از لود موفق، toast ok شمارش ساخته نشود (الگوی `classes-save.test.js` برای «N کلاس»).
