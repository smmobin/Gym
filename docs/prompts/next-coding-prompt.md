## پرامپت C — پیامک واقعی (provider ایرانی + env)

```text
# نقش
تو Agent سازندهٔ GYM CONTROL هستی (نه مدیر محصول).
docs را از docs/README.md خودت پیدا کن.
منبع حقیقت: docs/product/business-rules.md (اعلان و پیامک) و docs/guides/security.md.
فرض: ورود یکپارچه، پنل مربی، و درگاه پرداخت sandbox آماده‌اند — آن‌ها را بازنویسی نکن مگر باگ blocker.
کار فقط در frontend/ + backend/. Ocean Dark MPA. بدون React.
هیچ API Key / رمز پنل پیامک / .env واقعی در گیت نرود.

# زمینهٔ فعلی (تأیید در کد)
- صفحه/بخش قالب پیامک با دکمهٔ مرده و متن «هنوز آماده نیست» (مثلاً sms-templates.js).
- اعلان داخل‌برنامه برای کارکنان و ورزشکار هست؛ پیامک واقعی نیست.
- درگاه پرداخت جداست و تمام شده — به SMS قاطی نکن.

# هدف این برش
اتصال امن به یک سرویس پیامک ایرانی رایج با کلید فقط از env، طوری که:
1) وقتی SMS پیکربندی شده، کارکنان مجاز بتوانند از روی قالب‌ها برای یک عضو (موبایل ذخیره‌شده) ارسال آزمایشی/واقعی انجام دهند.
2) وقتی SMS خاموش است، UI همان «هنوز آماده نیست» بماند و دکمه کار نکند (رفتار فعلی نشکند).
3) هیچ OTP/لاگین با پیامک در این برش ساخته نشود (فراموشی رمز همچنان توسط مدیر/میز طبق قوانین فعلی).

Provider پیشنهادی: یکی از رایج‌های ایران (مثلاً کاوه‌نگار / غرفه‌ای مشابه) با adapter واحد تا بعداً عوض شود. نام را در env قابل‌تعویض نگه دار. اگر SDK رسمی دارید، کلید را فقط از Settings/env بخوان.

# داخل محدوده
Backend:
- env مثال (با الگوی Settings پروژه هم‌خوان کن):
  - SMS_PROVIDER=none|kavenegar|...
  - SMS_API_KEY=
  - SMS_SENDER= (اگر لازم)
  - SMS_ENABLED وابسته به provider+key غیرخالی
- GET وضعیت غیرحساس: enabled / provider / label (بدون افشای کلید) — شبیه gateway/status.
- POST ارسال: فقط نقش‌های مجاز (مدیر و منشی؛ مربی فقط اگر business-rules اجازه داد — پیش‌فرض: نه، مگر docs صریح بگوید).
  - ورودی: template_id یا متن قالب + member_id (موبایل از سرور؛ کلاینت شمارهٔ دلخواه نفرستد مگر مدیر صریحاً برای تست و با محدودیت).
  - جایگزینی متغیرهای قالب {{name}} و … روی سرور.
  - اگر provider خاموش → ۴۰۳ فارسی.
- لاگ audit ساده برای ارسال (چه کسی، به کدام member_id، کدام قالب، موفق/شکست) بدون ذخیرهٔ متن کامل حساس بیشتر از لازم.
- تست: pytest با mock HTTP provider (بدون شبکهٔ واقعی در CI)؛ disabled / happy / 403 نقش / عضو ناموجود.

Frontend (Ocean Dark):
- بخش قالب پیامک: اگر enabled، دکمهٔ ارسال زنده + انتخاب عضو (جستجو مثل میز) + پیام نتیجه.
- اگر disabled: همان تگ «هنوز آماده نیست».
- RTL فارسی؛ بدون نمایش API key.
- تست دود فرانت (mock).

Docs:
- getting-started: چطور با env تست شود؛ هشدار هزینه/اعتبار پنل واقعی.
- .env.example کلید خالی.
- roadmap-status و schema-todos را بعد از اتمام به‌روز کن.
- business-rules: جملهٔ «فقط دکمهٔ مرده» را به «وقتی env فعال است ارسال واقعی مجاز است؛ وگرنه placeholder» به‌روز کن.

# خارج از محدوده
- OTP ورود / فراموشی رمز با پیامک
- بازاریابی انبوه / کمپین هزارنفره
- دستکاری درگاه پرداخت یا ورود یکپارچه مگر blocker
- ذخیرهٔ کلید در گیت یا UI
- چندشعبه، فروشگاه کالا

# DoD

- commit/push طبق قانون Gym بعد از سبز.
- گزارش: OK یا ناقص + نام env + نحوهٔ تست با mock/sandbox provider.
```
