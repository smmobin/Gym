# پرامپت مرحلهٔ بعد — برای چت سازنده (Agent)

آخرین به‌روزرسانی: ۱۴۰۴-۰۷-۲۷ (مدیر محصول — پس از تأیید قفل پرونده)  
مرحله: گزارش هزینه / سود ساده برای مدیر

کل بلاک زیر را کپی کن و در یک **چت Agent جدید** (سازنده، نه مدیر محصول) بفرست.

```text
# نقش
تو Agent سازندهٔ پروژهٔ GYM CONTROL هستی. مدیر محصول این مرحله را تأیید کرده.
docs را خودت پیدا و بخوان (از docs/README.md شروع کن).
منبع حقیقت: docs/product/business-rules.md بخش پول / «هزینه و سود».
مدل موجود:
- backend/app/models/expense.py (Expense + ExpenseCategory)
- seed حداقل یک هزینه دارد
- پرداخت‌ها با status=paid منبع درآمد گزارش‌اند
کار جدید فقط در frontend/ و backend/. پروتوتایپ HTML ریشه را تغییر نده.

# زبان با صاحب پروژه
فارسی، ساده، داخل <div dir="rtl">.
در پایان بگو کاملاً OK یا ناقص + نتیجهٔ تست.

# هدف این چت (فقط همین برش)
فقط **مدیر** بتواند:
1) هزینه ثبت کند (دسته + تاریخ + مبلغ تومان + یادداشت اختیاری)
2) لیست هزینه‌ها را در بازهٔ تاریخ ببیند
3) خلاصه ببیند: درآمد (جمع پرداخت‌های paid در بازه) − هزینه‌ها = سود نمایشی
4) بدهی را با درآمد قاطی نکند (بدهی جدا یا اصلاً در این صفحه نباشد مگر برچسب واضح «بدهی ≠ درآمد»)

منشی و مربی → ۴۰۳ روی این APIها.

# داخل محدوده
Backend (/api/v1):

- GET /expenses?from=&to=  (فقط manager)
  لیست هزینه‌ها در بازه (تاریخ expense_date؛ پیش‌فرض ماه جاری تهران اگر خالی)
- POST /expenses  body: category, amount_toman (>=0), expense_date, note?
  category از ExpenseCategory موجود: rent, salary, purchase, utilities, other
  created_by_user_id = کاربر جاری
- PATCH /expenses/{id} اختیاری ساده؛ یا DELETE/حذف نرم — اگر سخت است فقط ایجاد+لیست کافی است و در گزارش بگو
- GET /reports/profit?from=&to=  (فقط manager)
  پاسخ تقریبی:
  {
    from, to,
    income_paid_toman,   // SUM payments where status=paid و تاریخ پرداخت در بازه
    expenses_toman,      // SUM expenses در بازه
    profit_toman         // income - expenses (می‌تواند منفی باشد)
  }
  تاریخ پرداخت: از فیلد تاریخ موجود Payment استفاده کن (created_at یا paid_at — هر کدام در مدل هست را مستند کن)
  refunded در درآمد نباشد

نقش: فقط StaffRole.manager؛ receptionist/trainer → ۴۰۳؛ بدون لاگین → ۴۰۱

Frontend:
- صفحهٔ /reports یا /manager/finance پشت لاگین مدیر
- فیلتر بازه تاریخ (ساده)
- کارت/خلاصه: درآمد / هزینه / سود (تومان با جداکننده)
- فرم ثبت هزینه + جدول لیست
- منشی اگر لینک را باز کرد پیام عدم دسترسی (و سرور ۴۰۳)
- RTL/فارسی؛ تاریخ در UI شمسی اگر الگوی پروژه هست وگرنه ISO با ذکر در گزارش
- فاکتور خرید / مالیات / تأمین‌کننده نساز

Seed / Docs:
- چند هزینه با دسته‌های مختلف در seed اگر کم است
- getting-started: چطور با لاگین مدیر گزارش را ببینند؛ تأکید منشی نمی‌بیند
- roadmap فقط اگر مطمئنی تمام شد

# خارج از محدوده (نساز)
- مهمان روزانه، فرم آزمایشی عمومی، تنظیمات باشگاه کامل
- قفل پرونده بیشتر، پنل ورزشکار
- پیامک / درگاه / حسابداری پیچیده / خروجی Excel اجباری
- تغییر HTML ریشه
- نشان دادن گزارش سود به منشی

# قوانین کسب‌وکار مرتبط (اجرا کن)
- مدیر هزینه را با دسته + تاریخ + مبلغ ثبت می‌کند
- سود نمایشی = درآمد پرداخت‌شده − هزینه‌ها
- درآمد گزارش = فقط پرداخت‌شده؛ بدهی جدا است
- فاکتور خرید/مالیات/تأمین‌کننده در v1 نیست
- منشی گزارش مالی مدیر را نمی‌بیند
- مخفی کردن UI امنیت نیست
```
