مرحله: پنل ورزشکار (لاگین + دادهٔ خودش)

کل بلاک زیر را کپی کن و در یک **چت Agent جدید** (سازنده، نه مدیر محصول) بفرست.

# هدف این چت (فقط همین برش)
ورزشکار با موبایل وارد شود و فقط دادهٔ خودش را ببیند:
1) لاگین/خروج ورزشکار (جدا از نشست کارکنان)
2) داشبورد ساده: عضویت‌ها، بدهی، پرداخت‌های خودش
3) دیدن برنامه(های) تمرینی خودش (فقط خواندن)
4) درخواست تمدید → اعلان برای کارکنان (بدون تمدید خودکار و بدون درگاه)
5) اعلان‌های مربوط به خودش (خواندن)
6) desk بتواند رمز اولیهٔ ورزشکار را ست کند
7) تست سبز سخت‌گیر روی مرز دسترسی (عضو A دادهٔ عضو B را نبیند)

# داخل محدوده

## احراز هویت ورزشکار
چون پیامک واقعی نیست:
- روی Member فیلد password_hash (nullable تا وقتی ست نشده)
- POST /api/v1/athlete/auth/login  { mobile, password } → cookie جدا مثلاً gym_athlete_session (HttpOnly, SameSite=Lax, Secure در prod)
- POST /api/v1/athlete/auth/logout
- GET /api/v1/athlete/auth/me
- مدل نشست ورزشکار جدا از staff sessions (یا ستون audience روی session موجود — یک طراحی واضح انتخاب و مستند کن)
- حداقل ۸ کاراکتر برای رمز
- آرشیو/نامعتبر → لاگین ممنوع

ست رمز توسط desk:
- POST /api/v1/members/{id}/athlete-password  فقط manager+receptionist
  body: password
- seed: حداقل ۲ عضو فعال با رمز توسعهٔ مشخص (مثلاً ChangeMe123) و در getting-started جدول بده
- فراموشی رمز ورزشکار نسخهٔ اول: desk عوض می‌کند (مثل کارکنان)

مسیر کارکنان و ورزشکار قاطی نشوند: cookieهای جدا؛ require_athlete و require_staff جدا.

## API دادهٔ ورزشکار (همه فقط «خودش»)
پیشوند پیشنهادی /api/v1/athlete/...
- GET /athlete/memberships  (+ debt_toman)
- GET /athlete/payments
- GET /athlete/workout-plans  (فقط خواندن)
- GET /athlete/notifications + mark read (اعلان‌هایی با audience ورزشکار / member_id خودش)
- POST /athlete/renewal-requests  body اختیاری note
  → یک staff notification از نوع renewal_request بساز (به desk)؛ تمدید خودکار نکن؛ پرداخت آنلاین نساز
- ویرایش محدود پروفایل اختیاری: فقط first_name/last_name اگر ارزان است؛ موبایل عوض کردن را سخت‌گیر یا ممنوع بگذار مگر desk

هر دسترسی به id عضو دیگر → ۴۰۳/۴۰۴ بدون افشا.

## Frontend
- /athlete/login
- /athlete (یا /athlete/home) داشبورد RTL
- بخش‌ها: اشتراک‌ها/بدهی، پرداخت‌ها، برنامه‌ها، درخواست تمدید، اعلان‌ها
- از شل کارکنان جدا باشد (ناو کارکنان دیده نشود مگر لینک خروج به عمومی)
- لینک کوچک از صفحهٔ خانه/لاگین کارکنان به «ورود ورزشکار» اختیاری
- تومان با جداکننده؛ تاریخ شمسی اگر الگوی پروژه هست

## Docs
- getting-started: چطور با موبایل seed وارد شوند؛ تأکید بدون پیامک/درگاه
- business-rules را بازنویسی کلی نکن؛ اگر نیاز به یک خط «لاگین ورزشکار فعال شد» در roadmap کافی است
- schema-todos در صورت فیلد جدید

# خارج از محدوده (نساز)

- درگاه آنلاین و تمدید خودکار بعد از پرداخت

# قوانین کسب‌وکار مرتبط (اجرا کن)
- ورزشکار فقط دادهٔ خودش را می‌بیند
- برنامه را فقط می‌بیند (نمی‌نویسد)
- تا درگاه آماده نیست: درخواست تمدید فقط اعلان برای کارکنان است
- پیامک واقعی نساز
- مخفی کردن UI امنیت نیست — سرور مرز member_id را enforce کند
