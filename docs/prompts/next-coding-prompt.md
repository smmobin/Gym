# هدف این چت (فقط همین برش)
منشی/مدیر بتوانند کلاس‌های گروهی را ببینند، برای عضو رزرو کنند، لغو کنند، و وقتی کلاس پر است سیستم جلوی رزرو بیش از ظرفیت را بگیرد (بدون overbook / بدون لیست انتظار).

1) لیست کلاس‌های فعال (با ظرفیت، تعداد رزرو booked، باقی‌مانده)
2) ساخت/ویرایش سادهٔ کلاس توسط manager (+ در صورت نیاز receptionist برای زمان‌بندی روزانه — حداقل: manager بسازد، receptionist رزرو کند؛ اگر ساده‌تر است هر دو desk بتوانند بسازند، در گزارش بگو)
3) رزرو عضو روی کلاس با enforce ظرفیت از helper موجود
4) لغو رزرو → جا آزاد شود
5) برچسب آقایان/بانوان/مختلط فقط نمایشی — رزرو را بر اساس جنسیت رد نکن (جنسیت روی عضو نیست)
6) تداخل ساعت همان مربی: هنگام ذخیرهٔ کلاس فقط هشدار در پاسخ/UI؛ ممنوع کامل نکن
7) UI React پشت لاگین (مثلاً /classes)
8) تست‌های سبز API + ظرفیت + نقش‌ها

# داخل محدوده
Backend (/api/v1) — نام‌ها می‌توانند کمی فرق کنند اگر واضح باشند:

کلاس‌ها:
- GET /group-classes  (فیلتر اختیاری: from/to یا upcoming؛ فقط is_active=true پیش‌فرض)
  پاسخ هر آیتم: id, title, trainer_user_id?, capacity, booked_count, remaining, gender_label, starts_at, ends_at, is_active
- POST /group-classes  (desk یا فقط manager — یک سیاست انتخاب و مستند کن)
  body: title, capacity (>0), gender_label, starts_at, ends_at, trainer_user_id?
  اگر ends_at <= starts_at → ۴۲۲
  اگر trainer_user_id کلاس دیگری با همپوشانی زمان دارد → باز هم ذخیره کن ولی در پاسخ warning برگردان (مثلاً trainer_schedule_conflict: true)
- PATCH /group-classes/{id}  اختیاری ولی مفید: عنوان/ظرفیت/زمان/فعال‌بودن
  کاهش capacity زیر تعداد booked فعلی → رد با خطای واضح

رزرو:
- GET /group-classes/{id}/bookings
- POST /group-classes/{id}/bookings  body: member_id
  قبل از insert: assert_can_book؛ اگر پر → ۴۰۹ Conflict (یا ۴۰۰ با detail واضح)
  عضو آرشیو/نامعتبر → ۴۰۰/۴۰۴
  رزرو تکراری همان عضو روی همان کلاس (در حالت booked) → ۴۰۹ به‌خاطر UniqueConstraint یا چک سرویس
  status پیش‌فرض booked
- POST /group-classes/{id}/bookings/{booking_id}/cancel  یا POST /bookings/{id}/cancel
  status → cancelled؛ cancelled_at پر شود؛ بعد از لغو، remaining افزایش یابد
  لغو دوبارهٔ همان رزرو → ۴۰۹/۴۰۰ بی‌ضرر

نقش‌ها:
- manager + receptionist: لیست، رزرو، لغو (و ساخت کلاس طبق سیاست بالا)
- trainer: فقط خواندن کلاس‌هایی که trainer_user_id اوست + لیست رزرو همان‌ها؛ رزرو/لغو/ساخت → ۴۰۳ (مگر بعداً محصول عوض شود)
- بدون لاگین → ۴۰۱

غیبت / مصرف جلسه از بستهٔ کلاس:
- منطق کامل «غیبت کلاس یک جلسه کم کند» را اگر گران است در این برش نساز؛ در schema-todos یا گزارش بنویس که مرحلهٔ بعد/هم‌زمان با حضور است.
- حداقل: رزرو و ظرفیت درست کار کند.

Frontend:
- صفحهٔ /classes پشت لاگین، RTL/فارسی
- لیست کلاس‌ها با ظرفیت باقی‌مانده و برچسب جنسیت نمایشی
- انتخاب عضو (جستجو مثل billing/attendance) → رزرو
- لغو رزرو
- فرم ساخت/ویرایش کلاس برای نقش مجاز
- اگر warning تداخل مربی آمد، در UI نشان بده ولی ذخیره را بلاک نکن
- تومان/شمسی اگر الگوی پروژه هست؛ وگرنه ISO موقتاً OK با ذکر در گزارش

Seed / Docs:
- اگر seed کلاس کافی نیست برای دمو UI، کمی غنی‌تر کن (چند کلاس upcoming با ظرفیت متفاوت، یکی نزدیک پر)
- getting-started: چطور /classes را امتحان کنند
- schema-todos: اگر قید/منطق جدیدی باز ماند به‌روز کن
- roadmap را فقط اگر مطمئنی تمام شد

- تداخل ساعت همان مربی: هشدار هنگام ذخیره؛ ممنوع کامل نیست
- مخفی کردن UI امنیت نیست — سرور نقش را enforce کند
