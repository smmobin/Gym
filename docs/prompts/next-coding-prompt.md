## هدف این برش (H) — تم تاریک پیش‌فرض + تم روشن قابل‌سوئیچ

سایت و پنل‌ها امروز فقط **Ocean Dark** هستند (متغیرهای CSS در `frontend/assets/css/ocean.css` روی `:root`).

صاحب می‌خواهد:

1) **پیش‌فرض برای هر بازدیدکننده = همان تم تاریک فعلی** (هیچ‌کس اول‌بار وارد light نشود مگر خودش انتخاب کند).
2) یک **تم روشن (light)** کامل و شیک که کل UI (لندینگ + لاگین + پنل مدیر/منشی/مربی + ورزشکار) با آن خوانا و یکدست باشد.
3) یک **کنترل سوئیچ‌مانند خیلی شیک** در منو برای جابه‌جایی dark ↔ light:
   - در صفحات پنل: داخل **سایدبار** (ترجیح: ناحیهٔ پایین منو نزدیک «صفحه اصلی / خروج»، یا جای ثابت واضح در منو) — کاربر گفت «سمت چپ منو»؛ در چیدمان فعلی سایدبار همان منوی کناری است؛ سوئیچ را آنجا بگذار، نه قایم در تنظیمات.
   - در لندینگ و لاگین: در **هدر/منوی بالا** جای ثابت و شیک (دسکتاپ + موبایل).
4) اگر عکس‌های لندینگ روی تم روشن بد به نظر می‌رسند (تیره/کنتراست کم)، طبق `project-rules` §۱۱ **خودت نسخه‌های مناسب light بساز/جنریت کن و وصل کن** — از صاحب اجازه نپرس. عکس واقعی عضو نساز.

## قوانین / قیود محصول

- کار فقط در `frontend/` (+ تست vitest + در صورت نیاز یک خط docs). بک‌اند/API برای تم لازم نیست مگر بخواهی preference سروری بسازی — **نساز**؛ ترجیح تم فقط سمت کلاینت کافی است.
- HTML ریشهٔ پروتوتایپ GitHub Pages را دست نزن مگر ضروری نباشد.
- RTL / فارسی / تومان خراب نشود.
- پیش‌فرض همیشه dark؛ اگر کاربر قبلاً light انتخاب کرده، با `localStorage` (کلید ثابت مثلاً `gym-theme`) همان را روی بازدید بعد اعمال کن.
- از `prefers-color-scheme` سیستم برای عوض کردن پیش‌فرض محصول استفاده **نکن** (صاحب گفت دیفالت سایت dark بماند). می‌توانی فقط به‌عنوان fallback وقتی هنوز هیچ انتخابی ذخیره نشده همان dark بماند.
- رنگ‌های hard-coded که فقط برای dark نوشته شده‌اند و متغیر CSS نیستند را تا حد معقول به توکن تم وصل کن تا light نشکند؛ refactor عظیم غیرضروری نکن.
- وردپرس / PWA / فاز آپلود لوگو از پنل / برش G لندینگ زندهٔ طرح‌ها — خارج از این برش مگر تداخل اجباری.

## داخل محدوده — پیاده‌سازی پیشنهادی

### الف) توکن‌های تم
- `:root` یا `html[data-theme="dark"]` = همان پالت Ocean Dark فعلی (رفتار پیش‌فرض).
- `html[data-theme="light"]` = پالت روشن هماهنگ (پس‌زمینه روشن، متن تیره، accent فیروزه‌ای/اقیانوسی حفظ شود تا برند یکسان بماند؛ بنفش/کرم کلیشه‌ای AI ممنوع طبق قوانین طراحی).
- `color-scheme: dark` / `light` روی html هماهنگ با تم.
- تا حد ممکن همهٔ سطوح (sidebar، topbar، کارت، جدول، فیلد، مودال date-picker و …) از متغیرها تغذیه شوند.

### ب) اعمال زودهنگام تم (ضد چشمک)
- یک اسکریپت خیلی کوچک **قبل از رنگ‌آمیزی صفحه** (inline در `<head>` صفحات اصلی یا ماژول اولیه‌ای که FOUC ندهد) تم ذخیره‌شده را روی `<html data-theme="...">` بگذارد تا فلش سفید/تیره دیده نشود.
- ماژول مشترک مثلاً `frontend/assets/js/theme.js`: `getTheme`, `setTheme`, `toggleTheme`, `initThemeToggle(rootEl)`.

### ج) سوئیچ UI — حتماً شیک
- کنترل به شکل **switch / segmented toggle** با آیکون ماه/خورشید یا معادل مینیمال، انیمیشن نرم، حالت `:focus-visible`، `aria-pressed` یا `role="switch"` + برچسب فارسی قابل دسترس (مثلاً «تم روشن» / «تم تاریک»).
- ظاهر سفارشی و هم‌تراز Ocean Dark — نه checkbox خام مرورگر.
- یک کامپوننت/مارک‌آپ مشترک در shell پنل‌ها و لندینگ/لاگین تا تکرار شلخته نشود.
- روی همهٔ صفحات محصول واقعی اعمال شود: `index.html` لندینگ، `/login/`، `/manager/`، `/receptionist/`، `/trainer/`، `/athlete/` (و لاگین ورزشکار اگر جداست).

### د) تصاویر لندینگ
- مسیر فعلی مثل `/images/hero-gym.jpg` و بقیه را بررسی کن.
- برای تم light: یا فایل‌های موازی (مثلاً `hero-gym-light.jpg`) با تعویض `src` هنگام تغییر تم، یا `<picture>` / атрибут data، یا اگر با CSS (filter/overlay) کیفیت شیک و خوانا می‌شود همان — اولویت با **ظاهر شیک** است نه هک زشت.
- طبق §۱۱ در صورت نیاز تصویر light را خودت جنریت/بساز و commit کن؛ PII واقعی نگذار.

### ه) تست و docs
- vitest: ذخیره/خواندن تم، toggle، پیش‌فرض dark وقتی storage خالی است؛ در صورت امکان وجود سوئیچ در مارک‌آپ shell/لندینگ.
- اشارهٔ کوتاه در getting-started یا ADR/نتیجه: تم پیش‌فرض dark؛ سوئیچ در منو؛ ترجیح در localStorage.
- اگر ADR 0005 فقط «Ocean Dark» می‌گوید، یک جملهٔ کوتاه اضافه کن که light به‌عنوان حالت اختیاری کاربر اضافه شد و dark پیش‌فرض ماند — بدون عوض کردن کل ADR مگر لازم.

## خارج محدوده
- همگام‌سازی تم با سرور / پروفایل کاربر در DB
- PWA، وردپرس، OTP، برش G قیمت لندینگ (جدا بماند)
- redesign کامل برند یا عوض کردن فونت اصلی
- اجبار light بر اساس OS

## معیار پذیرش
1. بازدید اول (بدون localStorage) = dark عین الان.
2. کلیک سوئیچ → light فوری؛ دوباره → dark؛ رفرش صفحه همان انتخاب آخر را نگه می‌دارد.
3. سوئیچ در منوی پنل (سایدبار) و در هدر لندینگ/لاگین دیده می‌شود و شیک است.
4. در light، متن/فرم/سایدبار خوانا و بدون کنتراست خراب؛ عکس‌های لندینگ مناسب light هستند.
5. تست سبز + commit/push به origin/main طبق قانون Gym؛ گزارش فارسی OK/ناقص به صاحب.
