## داخل محدوده

### الف) UI لاگین — حذف کامل دمو
فایل فعلی: `frontend/login/index.html` (+ استایل مرتبط در `frontend/assets/css/live.css` یا هر CSS که `.demo-accounts` / `.demo-table` دارد).

الزام:
- کل `<aside class="demo-accounts">` و جدول موبایل‌های دمو و متن «رمز مشترک seed: ChangeMe123» را حذف کن.
- هیچ شمارهٔ 09120000001 / 09120000002 / 09120000003 / 09121111001 و رمز ChangeMe123 روی UI لاگین یا لندینگ نماند.
- فرم ورود تمیز بماند: موبایل + رمز + دکمه؛ بدون کارت/جدول حساب نمونه.
- اگر بعد از حذف، CSS مردهٔ فقط-دمو ماند، پاکسازی سبک OK (بدون بازنویسی کل تم).
- صفحات redirect مثل `frontend/athlete/login.html` اگر اشاره به «حساب دمو» دارند اصلاح شوند؛ خود redirect به `/login/` بماند.

### ب) لندینگ `frontend/index.html` — حذف بخش ورود به سامانه
الان بعد از سکشن `#trial` (فرم جلسه آزمایشی + آدرس/ساعات) یک سکشن `#roles` هست با عنوان «ورود به سامانه» / کارت «ورود یکپارچه» و اشاره به حساب دمو.

الزام:
- کل سکشن `#roles` (از شروع `<section … id="roles">` تا بسته شدن همان section) را کاملاً حذف کن.
- از پایان سکشن trial/آدرس تا قبل از `<footer>` چیزی شبیه بلوک ورود باقی نماند.
- فوتر: لینک کوچک «ورود» به `/login/` می‌تواند بماند؛ متن تبلیغاتی مثل «لندینگ محصول · ورود یکپارچه…» و هر اشاره به حساب دمو را به متن خنثی باشگاه عوض کن (مثلاً فقط برند + لینک‌های عادی).
- لینک‌های منو که به `#roles` می‌روند اگر هست حذف/اصلاح کن.

### ج) هدر لندینگ — CTA ورود هم‌تراز جلسه آزمایشی
الان:
- «ورود به سامانه» فقط یک `<a href="/login/">` معمولی داخل `.site-links` است.
- «جلسه آزمایشی» دکمهٔ برجسته `.btn.nav-cta-desktop` (و روی موبایل `.btn.nav-cta-mobile`) است.

الزام طراحی (بدون کارت تزئینی اضافه؛ در همان زبان بصری Ocean Dark):
- «ورود به سامانه» را از حالت لینک معمولی خارج کن و به یک CTA دکمه‌ای در هدر تبدیل کن که از نظر اندازه/وزن بصری نزدیک «جلسه آزمایشی» باشد.
- پیشنهاد پیاده‌سازی قابل‌قبول (سازنده یکی را تمیز اجرا کند):
  - دسکتاپ: دو CTA کنار هم در ناحیهٔ CTA هدر — مثلاً `ورود به سامانه` (سبک secondary/ghost یا outline روی همان `.btn`) + `جلسه آزمایشی` (primary فعلی). لینک متنی تکراری ورود را از `.site-links` بردار تا دوبل نشود.
  - موبایل (منوی همبرگری): هر دو به‌صورت دکمهٔ full-width / برجسته داخل منو دیده شوند (مثل الگوی فعلی nav-cta-mobile برای trial؛ برای login هم معادل).
- فاصله، radius، و تایپوگرافی با `.btn` موجود هم‌خوان باشد؛ رنگ ورود با trial قاطی بصری نکند (سلسله‌مراتب: هر دو بزرگ، trial می‌تواند کمی قوی‌تر بماند).
- دسترسی‌پذیری: aria-label مناسب؛ فوکوس کیبورد حفظ شود.
- بعد از تغییر، لندینگ را در عرض دسکتاپ و ≤1100px چک کن که منو نشکند.

### د) دادهٔ فیک — آماده‌سازی مسیر خالی (نه دیپلوی هاست)
1) یک دستور امن wipe برای محیط توسعه اضافه کن، مثلاً:
   `python -m app.db.wipe_dev_data`
   - فقط وقتی APP_ENV شبیه production نیست (یا همان الگوی guard seed: در production-like ممنوع مگر فلگ صریح مخرب).
   - جدول‌های دامنهٔ seed/دمو را خالی کند (users کارکنان دمو، members، memberships، payments، … طبق همان ترتیبی که seed پاک می‌کند) تا DB برای شروع واقعی خالی شود.
   - schema/migration را خراب نکند؛ alembic را دوباره از صفر لازم نباشد مگر لازم فنی.
2) روی ماشین صاحب (لوکال): بعد از تست سبز، wipe را اجرا کن تا DB او از فیک خالی شود؛ سپس در گزارش بگو برای اولین ورود باید:
   `python -m app.db.bootstrap_manager --mobile … --password … --name …`
   را خودش با موبایل/رمز واقعی بزند (رمز را در گیت/چتHARDCODE نکن).
3) اسکریپت `app.db.seed` را حذف کامل نکن — برای pytest و دموی اختیاری توسعه‌دهنده بماند، ولی:
   - در UI هیچ ارجاعی نباشد
   - در getting-started مسیر پیش‌فرض = خالی + bootstrap باشد؛ seed را بخش «اختیاری فقط برای توسعه‌دهنده/تست» بنویس و بزرگ نکن
4) هر banner/hint داخل پنل‌ها که موبایل seed یا ChangeMe123 نشان می‌دهد را پیدا و حذف کن (grep روی frontend/).

## قوانین کسب‌وکار مرتبط (خلاصه)
- ورود یکپارچه: فقط موبایل+رمز؛ بدون انتخاب نقش؛ اولویت staff بر member.
- اولین مدیر روی سرور/لوکال خالی با bootstrap؛ نه با seed اجباری.
- Seed روی دادهٔ واقعی/production ممنوع (فلگ مخرب جدا).
- عضو واقعی و کارکنان از پنل ساخته می‌شوند؛ حذف دائمی ممنوع (غیرفعال/آرشیو).

## خارج از محدوده (انجام نده)
- دیپلوی واقعی روی لیارا/VPS/DNS/HTTPS (صاحب خودش بعداً)
- خرید دامنه، Cloudflare Tunnel، ngrok
- اجارهٔ جدا کمد / برش کمد صف‌تمدید (مگر باگ بلاکر این برش)
- OTP پیامکی، PWA، waitlist
- UI ساخت چندمدیر
- بازنویسی کل لندینگ یا عوض کردن تم Ocean Dark
- حذف کامل pytestهایی که از seed به‌عنوان fixture استفاده می‌کنند — fixture تست OK است
- commit کردن .env یا رمز واقعی

## تست و تحویل (اجباری)
- اگر wipe اضافه شد: تست واحد/ادغام که در production-like بدون فلگ refuse می‌کند؛ در حالت تست خالی‌سازی امن است.
- vitest/frontend: اگر تستی به وجود HTML دمو یا `#roles` وابسته است به‌روز کن؛ در صورت نیاز یک تست دود که login صفحه دیگر demo-accounts ندارد (مثلاً query متن ChangeMe123 / 09120000001 در fixture HTML یا smoke).
- pytest موجود سبز بماند (با seed در fixture تست).
- قبل از commit/push: `pytest` و `npm test` سبز.
- commit/push به origin/main طبق قانون Gym.
- روی لوکال صاحب: wipe را اجرا کن و تأیید کن لاگین با 09120000001 دیگر کار نمی‌کند تا bootstrap زده شود.
