# پرامپت‌های سازنده

آخرین به‌روزرسانی: ۱۴۰۴-۰۷-۲۹ (2026-10-21)  
**صاحب هنوز در چت مدیر محصول برای A تأیید «انجام شد» نداده.**  
الان **پرامپت A** را به سازنده بده (حتی اگر بخشی از کد از قبل در ریپو باشد).

بعد از تأیید PM → پرامپت B.

---

## پرامپت A — ورود یکپارچه + باگ نقش + پنل مربی (کپی کن)

```text
# نقش
تو Agent سازندهٔ GYM CONTROL هستی (نه مدیر محصول).
docs را از docs/README.md خودت پیدا کن. منبع حقیقت نقش‌ها: docs/product/business-rules.md (+ ظاهر Ocean Dark).
کار در frontend/ + backend/. React برنگردان.

# خیلی مهم — اول audit کن
ممکن است بخشی از این کار از قبل در main باشد (مثلاً کامیت‌های مربوط به unified login / trainer).
1) اول کد و تست‌ها را بررسی کن.
2) اگر همهٔ بندهای زیر واقعاً کامل و سبزند: هیچ بازنویسی بی‌خودی نکن؛ فقط گزارش بده «از قبل کامل بود» + چطور تست دستی شود + اگر docs ناقص است هم‌خوان کن.
3) اگر چیزی کم/خراب است: فقط همان حفره‌ها را ببند، commit/push کن.

# هدف‌های اجباری (همه باید برقرار باشند)
## الف) ورود یکپارچه (بدون انتخاب نقش)
- یک `/login/` فقط موبایل + رمز؛ بدون radio/dropdown نقش.
- لندینگ: یک CTA ورود؛ نه کارت‌های جدا برای انتخاب نقش به‌عنوان مسیر ورود اصلی.
- `/athlete/login.html` حذف یا redirect به `/login/`.
- سرور تشخیص نقش: staff اول (`users`)، بعد athlete (`members`)؛ کوکی درست؛ پاسخ kind+role.
- تداخل موبایل: اولویت staff.
- redirect: manager→/manager/ ، receptionist→/receptionist/ ، trainer→/trainer/ ، athlete→/athlete/

## ب) باگ منشی→مدیر + دمو
- هیچ پیش‌فرض موبایل مدیر روی input نباشد.
- جدول دمو روی صفحه ورود: 09120000001 مدیر، 0002 منشی، 0003 مربی، 09121111001 ورزشکار؛ رمز seed فقط برای dev.
- لاگین 0002 واقعاً receptionist و پنل منشی؛ نه مدیر.

## ج) پنل مربی
- `/trainer/` واقعی (نه فقط پرتاب به receptionist/#workouts).
- فقط شاگردان خودش؛ برنامه/حضور طبق business-rules؛ بدون گزارش مالی مدیر و تنظیمات حساس.
- سرور 403 برای عضو غیرشاگرد.

# تست و DoD
- تست‌های مرتبط سبز؛ در صورت تغییر: commit/push طبق قانون Gym.
- گزارش: کاملاً OK یا ناقص + فهرست چیزهایی که از قبل بود vs چیزهایی که ساختی.

# خارج از محدوده
- درگاه پرداخت، پیامک واقعی، دیپلوی با credential صاحب.
```

## پرامپت B — درگاه پرداخت (فقط بعد از تأیید A توسط صاحب در چت PM)

```text
# نقش
تو Agent سازندهٔ GYM CONTROL هستی. docs را از docs/README.md بخوان.
فرض: پرامپت A توسط صاحب تأیید شده. کار در frontend/ + backend/. Ocean Dark. بدون React. secrets در گیت نرود.

# هدف
درگاه ایرانی (پیشنهاد زرین‌پال) sandbox:
- ورزشکار پرداخت online برای تمدید/بدهی خودش شروع کند.
- verify فقط سروری؛ موفق → paid + رسید + renew با سرویس billing موجود.
- اگر gateway خاموش: «هنوز آماده نیست» + درخواست تمدید desk.

# داخل محدوده
env فقط (PROVIDER / MERCHANT_ID / SANDBOX / CALLBACK_URL)؛ adapter؛ idempotent callback؛ pytest mock؛ UI Ocean Dark athlete + فلگ میز؛ .env.example خالی؛ docs.

# خارج از محدوده
پیامک، ذخیره کارت، waitlist، دستکاری ورود یکپارچه مگر blocker.

# DoD
تست سبز، commit/push، گزارش OK/ناقص + نحوهٔ تست sandbox.
```
