# پرامپت مرحلهٔ بعد — برای چت سازنده (Agent)

آخرین به‌روزرسانی: ۱۴۰۴-۰۷-۲۵ (مدیر محصول — پس از تأیید auth)  
مرحله: برش عمودی لیست + ثبت عضو (API محافظت‌شده + حداقل UI)

کل بلاک زیر را کپی کن و در یک **چت Agent جدید** (سازنده، نه مدیر محصول) بفرست.

---

```text
# نقش
تو Agent سازندهٔ پروژهٔ GYM CONTROL هستی. مدیر محصول این مرحله را تأیید کرده.
docs را خودت پیدا و بخوان (از docs/README.md شروع کن).
منبع حقیقت رفتار: docs/product/business-rules.md
امنیت و auth موجود: docs/guides/security.md + کد فعلی auth (cookie نشست، get_current_user، require_roles).
کار جدید فقط در frontend/ و backend/. پروتوتایپ HTML ریشه را تغییر نده.

# زبان با صاحب پروژه
فارسی، ساده، داخل <div dir="rtl">. اصطلاح فنی را یک جمله توضیح بده.
در پایان بگو کاملاً OK یا ناقص + نتیجهٔ تست.

# هدف این چت (فقط همین برش)
اولین ارزش عملیاتی باشگاه: کارکنان واردشده بتوانند اعضا را ببینند و عضو جدید ثبت کنند.

1) API لیست اعضا (با فیلتر معقول: جستجوی نام/موبایل، وضعیت؛ پیش‌فرض آرشیو را پنهان کن مگر صریحاً خواسته شود)
2) API ثبت عضو جدید
3) API جزئیات یک عضو + ویرایش نام/موبایل/یادداشت/تاریخ تولد (طبق نقش)
4) آرشیو (soft) به‌جای حذف — بدون DELETE فیزیکی
5) حداقل UI React پشت لاگین: لیست + فرم ثبت ساده (فارسی/RTL)
6) تست خودکار سبز: 401 بدون نشست، نقش اشتباه، موبایل تکراری، تولید display_id، آرشیو

# داخل محدوده
Backend (پیشوند /api/v1):
- GET    /members
- POST   /members
- GET    /members/{id}
- PATCH  /members/{id}   (ویرایش فیلدهای مجاز)
- POST   /members/{id}/archive   (یا PATCH status=archived + archived_at) — حذف سخت ممنوع

فیلدهای ثبت/نمایش (business-rules):
- first_name, last_name, mobile (اجباری، یکتا)
- birth_date اختیاری، notes اختیاری
- بدون کد ملی، بدون عکس
- display_id خودکار ترتیبی مثل M-1001، M-1002، … (از seed/موجودی فعلی ادامه بده؛ یکتا)
- وضعیت اولیهٔ عضو جدید: pending (هنوز پرداخت/فعال‌سازی نشده — در این برش عضویت/پرداخت نساز مگر لازم نباشد)

نقش‌ها:
- manager و receptionist: لیست همه (غیرآرشیو به‌صورت پیش‌فرض) + ثبت + ویرایش + آرشیو
- trainer: فقط اعضای شاگرد خودش را در لیست/جزئیات ببیند (از trainer_member assignments فعال)؛ ثبت عضو جدید و آرشیو برای مربی ممنوع → 403
- بدون لاگین → 401

سایر:
- از deps موجود auth استفاده کن؛ چرخ را دوباره اختراع نکن
- اعتبارسنجی Pydantic؛ موبایل یکتا → خطای واضح فارسی یا کد خطای قابل‌نمایش در UI
- قفل پروندهٔ ۵دقیقه‌ای در schema-todos است — در این برش اگر ساده نیست، نساز؛ یک خط TODO در docs/product/schema-todos.md بگذار که «هنوز برای PATCH عضو نیامده»
- seed موجود باید با لیست کار کند؛ اگر display_id بعدی را درست حساب می‌کنی، seed را نشکن
- در صورت نیاز یک خط در getting-started: چطور صفحهٔ اعضا را بعد از لاگین باز کنند

Frontend:
- مسیر ساده پشت لاگین (اگر کاربر لاگین نیست → /login)
- لیست اعضا از API (نام، موبایل، display_id، وضعیت)
- فرم ثبت عضو جدید
- نیازی به داشبورد کامل منشی/مدیر نیست؛ تم با اسکلت فعلی هماهنگ و RTL/فارسی
- مبالغ/اشتراک/حضور در این UI نباشد

Docs:
- getting-started را در حد لازم به‌روز کن
- roadmap-status را فقط اگر مطمئنی این برش تمام شد علامت بزن؛ وگرنه مدیر محصول بعداً
```
