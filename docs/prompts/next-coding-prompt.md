# هدف این چت (فقط همین برش)
اگر دو نفر هم‌زمان روی یک عضو کار حساس کنند (تمدید/پرداخت/ویرایش/حضور)، نفر دوم قفل ببیند و نتواند عملیات حساس را پیش ببرد تا قفل آزاد شود یا ۵ دقیقه از آخرین تمدید قفل بگذرد.

1) مدل/جدول قفل پرونده (member_id یکتا برای قفل فعال، holder user_id، last_seen_at)
2) API: گرفتن قفل، ضربان (touch)، آزادسازی، وضعیت قفل
3) انقضای خودکار ۵ دقیقه از last_seen_at (بدون کرون اجباری: هنگام acquire/check منقضی‌ها پاک/نادیده)
4) عملیات حساس اگر قفل دست کس دیگری است → ۴۰۹ با اطلاعات holder
5) UI: در /billing و حداقل یک صفحهٔ حساس دیگر (اعضا یا حضور) قفل را بگیر/نگه دار/آزاد کن + پیام واضح
6) تست سبز

# داخل محدوده
Backend:

مدل پیشنهادی `member_file_locks` (نام آزاد است):
- member_id PK یا unique
- locked_by_user_id
- last_seen_at (timezone-aware)
- acquired_at
Migration Alembic لازم است.

API (/api/v1):
- POST /members/{id}/lock  → اگر آزاد یا منقضی یا متعلق به خودت: قفل مال تو؛ اگر دست دیگری و تازه: ۴۰۹ + { locked_by, locked_by_name?, expires_at }
- POST /members/{id}/lock/touch  → فقط holder؛ last_seen_at را تازه کن؛ وگرنه ۴۰۳/۴۰۹
- POST /members/{id}/unlock  → holder یا manager می‌تواند اجباری باز کند (سیاست: holder + manager؛ در گزارش بنویس)
- GET /members/{id}/lock  → وضعیت فعلی (locked?, holder, expires_at)

TTL: ۵ دقیقه از last_seen_at. ثابت در تنظیمات کد OK؛ بعداً به gym_settings وصل نشود مگر ارزان باشد.

Enforce روی عملیات حساس (حداقل):
- PATCH /members/{id}
- POST renew membership / payments / refund مربوط به آن عضو
- POST attendances/check-in برای آن member_id
قانون: اگر قفل فعال دست user دیگری است → ۴۰۹؛ اگر قفل نداری یا مال خودت است → اجازه (مال خودت) ؛ اگر قفل نیست → اجازه بده ولی در UI توصیه به acquire (سخت‌گیری سرور: یا «باید قفل مال تو باشد» یا «فقط اگر قفل دیگران است رد کن»). 
پیشنهاد امن و ساده برای v1: **اگر قفل فعال متعلق به دیگری است رد کن؛ اگر قفل نیست یا مال خودت است اجازه بده** (نفر اول بدون acquire هم کار می‌کند؛ نفر دوم اگر اولی acquire کرده گیر می‌کند). در گزارش سیاست را بنویس.
اگر می‌خواهی سخت‌گیرانه‌تر: عملیات حساس فقط با قفل متعلق به خودت — آن را انتخاب کن اگر UI را همه‌جا وصل می‌کنی.

نقش‌ها: staff لاگین‌شده؛ trainer فقط روی شاگرد خودش حق acquire (هم‌خوان با members).

Frontend:
- هنگام ورود به جریان حساس عضو در /billing (الزامی) و ترجیحاً /members ویرایش یا /attendance: acquire
- هر ~۶۰ثانیه touch تا صفحه باز است
- unlock در unmount / خروج از عضو / دکمهٔ آزادسازی
- اگر ۴۰۹ قفل: نام/موبایل holder و زمان انقضا را نشان بده
- RTL/فارسی

Docs:
- getting-started: چطور با دو مرورگر/دو نقش قفل را امتحان کنند
- schema-todos: قفل را انجام‌شده علامت بزن
- roadmap فقط اگر مطمئنی تمام شد
