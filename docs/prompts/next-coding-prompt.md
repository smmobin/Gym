# پرامپت مرحلهٔ بعد — برای چت سازنده (Agent)

آخرین به‌روزرسانی: ۱۴۰۴-۰۷-۲۷ (مدیر محصول — پس از تأیید پنل ورزشکار)  
مرحله: آماده‌سازی استقرار واقعی (هاست + HTTPS + بکاپ/restore)

کل بلاک زیر را کپی کن و در یک **چت Agent جدید** (سازنده، نه مدیر محصول) بفرست.

---

```text
# نقش
تو Agent سازندهٔ پروژهٔ GYM CONTROL هستی. مدیر محصول این مرحله را تأیید کرده.
docs را خودت پیدا و بخوان (از docs/README.md شروع کن).
منبع حقیقت استقرار/امنیت: docs/guides/security.md ، business-rules بخش بکاپ، project-rules.
فیچر محصول کارکنان+ورزشکار روی لوکال آماده‌اند. این برش **کد فیچر کسب‌وکار جدید نیست** — آماده‌سازی برای رفتن روی هاست واقعی است.
کار در frontend/ و backend/ و docs/guides/ ؛ HTML ریشه را محصول واقعی نکن.
رمز، .env واقعی، و دادهٔ عضو واقعی وارد گیت نکن.

# زبان با صاحب پروژه
فارسی، ساده، داخل <div dir="rtl">.
در پایان بگو کاملاً OK یا ناقص + نتیجهٔ تست (اگر تست جدید نوشتی).

# هدف این چت (فقط همین برش)
صاحب پروژه بتواند بدون حدس، سامانه را روی هاست واقعی (ترجیح مسیر ایرانی مثل لیارا یا VPS لینوکس) بالا بیاورد، HTTPS داشته باشد، و بکاپ/restore Postgres را یک‌بار تمرین کند.

1) راهنمای استقرار فارسی و عملی در docs
2) اسکریپت/دستور بکاپ و restore Postgres (قابل اجرا روی ویندوز dev و لینوکس سرور)
3) چک‌لیست production (SECRET، cookie Secure، CORS، DEBUG خاموش، seed روی prod ممنوع)
4) حداقل پشتیبانی فنی در کد/کانفیگ برای prod (مثلاً تنظیمات env، build فرانت، سرو استاتیک یا دستور جدا)
5) اختیاری اگر ارزان: Dockerfile / docker-compose برای مسیر VPS
6) تست کوچک برای هر منطق جدید (مثلاً اگر اسکریپت Python بکاپ نوشتی، یا تنظیمات config)

# داخل محدوده

## Docs (اجباری)
بساز یا تکمیل کن:
- docs/guides/deploy.md — گام‌به‌گام:
  الف) مسیر پیشنهادی اول: PaaS ایرانی (لیارا یا معادل) — اپ بک‌اند + Postgres جدا + فرانت build
  ب) مسیر جایگزین: VPS Ubuntu + Docker/systemd
  - دامنه + HTTPS
  - متغیرهای محیطی لازم (از .env.example بدون افشای رمز)
  - alembic upgrade head روی سرور
  - تأکید: seed فقط توسعه؛ روی دادهٔ واقعی هرگز seed پاک‌کننده اجرا نشود
  - GitHub Pages همچنان فقط ماکت است
- docs/guides/backup.md — بکاپ هفتگی دستی، محل جدا از لپ‌تاپ تنها، یک‌بار تست restore، دستورها
- لینک از docs/README.md و به‌روز کردن getting-started «مرحلهٔ بعد»

## بکاپ / restore
- اسکریپت در مثلاً backend/scripts/backup_db.py یا .ps1/.sh که از DATABASE_URL بخواند و dump بگیرد
- اسکریپت/دستور restore با هشدار مخرب‌بودن
- در docs بنویس خروجی را کجا بگذارند (خارج از ریپو؛ پوشهٔ بکاپ در .gitignore اگر لازم)

## Production readiness در کد/کانفیگ
- .env.example را کامل و واضح کن: SECRET_KEY قوی، ENVIRONMENT=production، cookie Secure، CORS_ORIGINS دامنهٔ واقعی، DATABASE_URL
- اگر اپ فقط روی 127.0.0.1 bind است، برای prod راهنما/تنظیم host مناسب
- فرانت: دستور build و اینکه VITE_API_BASE_URL در prod چه باشد (یا same-origin پشت پروکسی)
- اگر الان cookie Secure فقط با فلگ env است، مطمئن شو در docs آمده
- health چک برای orchestration اگر لازم

## Docker (اختیاری ولی توصیه‌شده اگر زیر ۱ جلسه تمام می‌شود)
- Dockerfile بک‌اند و/یا docker-compose با سرویس api + اختیاری postgres برای VPS
- نه اینکه حتماً لیارا را با Docker مجبور کنی اگر لیارا روش خودش را دارد — هر دو مسیر را در docs پوشش بده

## حفرهٔ کوچک محصولی (اختیاری اگر وقت ماند)
- وصل کردن UI قفل پرونده به صفحهٔ ویرایش اعضا (سرور از قبل soft-enforce دارد)
وگرنه در گزارش بگو عمداً نساختی.

# خارج از محدوده (نساز)
- خرید واقعی هاست / وارد کردن کارت / دیپلوی واقعی روی اکانت صاحب (مگر صاحب صریحاً credential بدهد — نده در گیت)
- پیامک واقعی، درگاه واقعی
- فیچر freeze عضویت، رزرو کلاس ورزشکار (حفرهٔ محصولی جدا؛ این برش استقرار است)
- بازنویسی کل معماری
- commit کردن .env یا dump واقعی دیتابیس

# قوانین مرتبط (اجرا کن)
- قبل از دادهٔ واقعی: بکاپ هفتگی + یک‌بار restore
- سرور مرجع امنیت است؛ HTTPS در prod
- هیچ رمز در گیت نباشد
- Prototype HTML ≠ محصول

# کیفیت
- اگر اسکریپت Python نوشتی: تست یا dry-run مستند
- اگر فقط docs: در گزارش بگو «docs-only برای بخش X» طبق قانون testing پروژه
- بعد از سبز بودن کارهای تست‌دار: commit + push به origin/main
- گزارش به صاحب: مسیر لیارا vs VPS، کجا بکاپ بگیرد، چه envهایی اجباری است، Docker آمد یا نه، چه چیز عمداً نساختی

# اگر مبهم شد
حدس نزن برای credential. مسیرها را ساده و کپی‌کردنی بنویس. جزئیات فرعی را مستند کن.
```
