# پرامپت مرحلهٔ بعد — برای چت سازنده (Agent)

آخرین به‌روزرسانی: ۱۴۰۴-۰۸-۲۰ (2026-11-10)  
**وضعیت صف:** Slice J **انجام‌شده** — صف پیشنهادی بعدی: سخت‌کردن دیپلوی HTTPS (بعد از تأیید صاحب)

---

## اگر صاحب گفت برو سراغ هاست / HTTPS — پرامپت کامل

```text
تو Agent توسعهٔ GYM CONTROL هستی. docs را خودت پیدا کن (guides/deploy.md، guides/backup.md، guides/security.md، guides/logging.md، product/roadmap-status.md، backend/.env.example). لیست URL از صاحب نخواه.

## هدف
آماده‌سازی و سخت‌کردن مسیر دیپلوی واقعی با HTTPS — بدون گذاشتن secret در گیت، بدون seed روی DB واقعی، و با چک‌لیست قابل‌اجرا برای صاحب روی لیارا/VPS.

## داخل محدوده
1. خواندن وضعیت فعلی deploy/config: cookie Secure، CORS، APP_ENV، SERVE_FRONTEND، خاموش بودن /docs در prod، مسدود بودن seed مخرب.
2. شکاف‌های کدی کوچک را ببند اگر واقعاً خطرناکند (مثلاً هشدار واضح‌تر وقتی APP_ENV=production ولی SECRET_KEY ضعیف؛ یا LOG_DIR روی PaaS).
3. `docs/guides/deploy.md` را با واقعیت کد هم‌خوان و عملی‌تر کن: ترتیب دقیق env، alembic، بالا آوردن، اولین مدیر با bootstrap_manager، اتصال فرانت به API روی دامنه HTTPS.
4. یک اسکریپت یا بخش docs برای «چک سلامت بعد از دیپلوی» (health، لاگین، بدون فاش کردن دمو).
5. تست: هر تغییر رفتاری بک‌اند → pytest مرتبط سبز. docs-only اگر هیچ کد عوض نشد بگو تست اجباری نبود.

## خارج محدوده
- ثبت‌نام/پرداخت هاست به‌جای صاحب
- commit کردن .env یا کلید واقعی
- فیچر محصول جدید (فروشگاه، شعبه، …)
- باز کردن URL عمومی برای خواندن backend/logs
- تغییر GitHub Pages پروتوتایپ به‌عنوان محصول واقعی

## تحویل
گزارش فارسی: چه چیزی از قبل OK بود، چه چیزی عوض شد، صاحب دقیقاً چه env و چه کلیک‌هایی در پنل هاست انجام دهد. commit/push بدون secret.
```
