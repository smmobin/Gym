# نقش

docs را خودت پیدا و بخوان (از docs/README.md شروع کن).

# هدف این چت (فقط همین برش)
منشی/مدیر بتوانند کمدها را ببینند، به عضوی که طرح/عضویت شامل‌کمد دارد کمد واگذار کنند، و کمد را آزاد کنند. اجارهٔ جدا/ماهانه برای کمد در نسخهٔ اول ساخته نشود.

1) لیست کمدها با وضعیت آزاد / اشغال (+ عضو فعلی اگر اشغال)
2) ساخت کمد جدید با کد یکتا (مثلاً L-03) — حداقل برای manager؛ اگر desk هر دو بتوانند، در گزارش بگو
3) واگذاری: فقط اگر عضو عضویت فعال با plan.includes_locker=true دارد
4) آزادسازی: released_at پر شود؛ کمد دوباره آزاد شود
5) یک کمد در یک زمان فقط یک واگذاری فعال (released_at IS NULL) — در سرویس enforce کن
6) UI React پشت لاگین (مثلاً /lockers)
7) تست‌های سبز برای قوانین بالا + نقش‌ها

# داخل محدوده
Backend (/api/v1):

کمدها:
- GET /lockers
  هر آیتم: id, code, is_active, is_free (یا status), current_assignment? { id, member_id, member_name?, membership_id?, assigned_at, note }
- POST /lockers  body: code (غیرخالی، یکتا), is_active؟
  کد تکراری → ۴۰۹/۴۰۰
- PATCH /lockers/{id} اختیاری: is_active؛ غیرفعال کردن کمدِ اشغال‌شده یا رد کن یا اول آزادسازی بخواه — یک سیاست ساده انتخاب و مستند کن

واگذاری:
- POST /lockers/{id}/assign
  body: member_id, membership_id? (اگر نداد، سرویس یک عضویت فعالِ شامل‌کمد برای همان عضو پیدا کند؛ اگر چند تا بود و مبهم بود → ۴۰۰ بخواه صریح بفرستد یا اولین را بگیر و در گزارش بگو), note?
  قوانین:
  - کمد باید active و بدون واگذاری فعال باشد وگرنه ۴۰۹
  - عضو باید وجود داشته باشد و آرشیو نباشد
  - باید عضویت مرتبط includes_locker=true و status مناسب فعال/معتبر باشد (منقضی/لغو شده قبول نباشد)
  - اگر عضو از قبل کمد فعال دیگری دارد: یا رد با پیام واضح، یا آزادسازی قبلی اجباری — پیشنهاد: رد با ۴۰۹ «عضو الان کمد دارد» (ساده و امن)
  - بدون طرح شامل‌کمد → ۴۰۰ با detail فارسی/واضح که اجارهٔ جدا در v1 نیست
- POST /lockers/{id}/release  یا POST /locker-assignments/{id}/release
  فقط اگر واگذاری فعال دارد؛ released_at = now؛ دوباره assign مجاز شود
  آزادسازی تکراری → ۴۰۹/۴۰۰ بی‌ضرر

خواندن برای عضو (اختیاری مفید):
- GET /members/{id}/locker  یا فیلد در جزئیات عضو — اگر ارزان است

نقش‌ها:
- manager + receptionist: لیست، assign، release، ساخت کمد (طبق سیاست)
- trainer: فقط خواندن ممنوع یا فقط مشاهدهٔ شاگرد خودش اگر لازم — پیش‌فرض: عملیات کمد برای trainer → ۴۰۳؛ لیست هم ۴۰۳ مگر خیلی لازم UI (ترجیح: desk-only)
- بدون لاگین → ۴۰۱

Frontend:
- صفحهٔ /lockers پشت لاگین، RTL/فارسی
- جدول/لیست: کد کمد، وضعیت، نام عضو، دکمهٔ واگذاری / آزادسازی
- واگذاری: انتخاب عضو (+ اگر لازم انتخاب عضویت شامل‌کمد) + یادداشت اختیاری
- اگر عضو طرح شامل‌کمد ندارد، پیام واضح نشان بده (نه اجارهٔ جدا)
- ساخت کمد جدید برای نقش مجاز
- الگوی جستجوی عضو مثل /billing یا /attendance

Seed / Docs:
- اگر فقط ۲ کمد کم است برای دمو، چند کمد آزاد اضافه کن؛ حداقل یک اشغال و چند آزاد
- getting-started: چطور /lockers را امتحان کنند
- schema-todos: یکتایی واگذاری فعال را اگر با چک سرویس حل شد به‌روز کن (قید جزئی Postgres اختیاری)
- roadmap را فقط اگر مطمئنی تمام شد

# خارج از محدوده (نساز)
- اجارهٔ ماهانهٔ جدا برای کمد / پرداخت مخصوص کمد
- پنل مربی، برنامه تمرینی، کلاس بیشتر
- قفل پرونده، گزارش مالی مدیر، مهمان روزانه، فرم آزمایشی
- لاگین ورزشکار، پیامک، درگاه
- تغییر HTML ریشه
- over-engineering با partial unique index مگر ساده و تست‌شده باشد — چک سرویس کافی است اگر تست پوشش دهد

# قوانین کسب‌وکار مرتبط (اجرا کن)
- مدیریت واگذاری و آزادسازی هست
- اجارهٔ جدا ندارد؛ فقط اگر طرح شامل کمد باشد واگذار می‌شود
- بدون طرح شامل‌کمد، نسخهٔ اول اجارهٔ ماهانهٔ جدا نمی‌سازد
- مخفی کردن UI امنیت نیست — سرور نقش و includes_locker را enforce کند
