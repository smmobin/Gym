# دفتر درخواست‌های صاحب پروژه (به زبان خودش)

**تاریخ ثبت:** ۱۴۰۴-۰۸-۰۴ (2026-10-26)  
**منبع:** ترنسکریپت واقعی چت‌های Cursor روی ریپوی Gym — نه حدس، نه خلاصهٔ کارهای Agent  
**هدف:** برای پروژهٔ بعدی ببینی *چه جور چیزهایی* معمولاً از AI می‌خواهی؛ و الگوی حرف‌زدن قابل‌تکرار باشد.

## این سند چیست / نیست

| هست | نیست |
|-----|------|
| خلاصهٔ درخواست‌هایی که **خود صاحب** با زبان خودش گفته | پرامپت‌های سازنده‌ای که مدیر محصول نوشته |
| مرتب‌شده بر اساس چت/فاز واقعی | فهرست تک‌تک «انجام شد» یا لاگ ترمینال |
| قابل کپی به‌عنوان چک‌لیست ذهن برای پروژهٔ بعد | جایگزینی `roadmap-status` یا `business-rules` |

**پوشش ترنسکریپت در زمان ثبت:** چت‌های `ADR + Structure`، `Business Rules`، `Product Management Gym _1`، `Product Management Gym _2`. چت‌های فقط‌سازنده با پرامپت paste‌شده اینجا دانه‌دانه نیامده‌اند.

---

## الگوی تکراری صاحب (برای پروژهٔ بعد)

1. نقش و مرز چت را قفل کن (مدیر محصول / سازنده / QA جدا).
2. بخواه Agent خودش docs را پیدا کند؛ با تو ساده حرف بزند.
3. برای ساخت فیچر: «پرامپت کامل بده؛ اینجا کد نزن» مگر صریح بگویی همین‌جا پیاده کن.
4. بعد از کار سازنده: «انجام شد» → مدیر محصول هم‌خوانی docs/کد را بگوید OK یا نه.
5. تصمیم محصولی را صریح بگو (مثلاً بدون دمو، ورود یکپارچه، PWA بعداً).
6. گیجی عملی (Pages در برابر لوکال، هاست، تونل، دمو به کارفرما) را جدا از فیچر بپرس.

مرتبط: [product-manager.md](product-manager.md)، [principled-project-playbook.md](principled-project-playbook.md)، [collaboration.md](collaboration.md).

## ب) مدیر محصول Gym _1 — درخواست‌های مهم

| # | خلاصهٔ درخواست صاحب |
|---|---------------------|
| ۷ | نقش PM: کجاییم، مرحلهٔ بعد، چه کار نکنم، پرامپت کامل سازنده |
| ۸ | مسیر قابل‌تکرار از اول پروژه تا الان برای پروژه‌های بعدی |
| ۹ | همان مسیر را برای تست/docs/ساختار/مشخصات/پروتوتایپ خیلی دقیق‌تر کامل کن |
| ۱۰ | فقط لیست مراحل باقی‌مانده تا تمام شدن پروژه — بدون پرامپت |
| ۱۱ | توضیح گیجی: GitHub Pages در برابر لوکال/پورت API؛ بعد پرامپت مرحلهٔ بعد |
| ۱۲ | هاست ایرانی مناسب Postgres/بک‌اند + مشخصات CPU/RAM/باند + مقایسه |
| ۱۳ | دمو به کارفرما از گوشی با بک‌اند روی لپ‌تاپ (بدون بردن لپ‌تاپ) |
| ۱۴ | انتخاب تونل (Cloudflare / ngrok / …)؛ رایگان، سرعت، مناسب محدودیت پرداخت |
| ۱۵ | فرانت موقت با پروتوتایپ فرق دارد؛ موقت است یا نهایی؟ |
| ۱۶ | فرانت اصلی Ocean Dark را به بک‌اند وصل کن؛ موقت را حذف؛ HTML/CSS/JS را در `frontend/` جدا کن؛ پرامپت سازنده |
| ۱۷ | ورود یکپارچه بدون انتخاب نقش روی UI؛ سامانه نقش را از موبایل+رمز بفهمد؛ باگ ورود منشی؛ نقش مربی طبق docs؛ در چت PM کد نزن — پرامپت بده (حتی دو پرامپت) |
| ۱۸ | ممیزی ریپو/گیت‌هاب؛ commit/push و به‌روز docs در صورت نیاز؛ اگر مرحلهٔ قبلی واقعاً انجام نشده همان پرامپت را دوباره بده |
| ۱۹ | صف پرامپت اشتباه بود (مربی انجام شد، درگاه نه) — docs را درست کن و فقط پرامپت درگاه را بده |
| ۲۰ | آیا به نقش QA نیاز دارم؟ QA چیست؟ |
| ۲۱ | پرامپت راه‌اندازی چت QA مستقل |
| ۲۲ | مشکل واگذاری کمد وقتی طرح شامل‌کمد هنوز فعال نشده — چه کنم؟ |
| ۲۳ | آماده‌سازی شبیه پروداکشن: بدون حساب/دمو روی UI؛ حذف بلوک ورود از لندینگ؛ CTA ورود بزرگ؛ پرامپت کامل؛ از این به بعد همیشه پرامپت کامل بچسبان |
| ۲۴ | پرامپت کوتاه برای باز کردن چت PM مشابه در چت دیگر |

*(در همان چت درخواست‌های کوتاه پشتیبانی هم بوده: رمز Postgres، اجرای پروژه، توضیح دستورها، خطای bootstrap — عمداً در جدول اصلی نیامده.)*

## ج) مدیر محصول Gym _2 — دانه‌دانه (همین دوره)

| # | خلاصهٔ درخواست صاحب |
|---|---------------------|
| ۱ | راه‌اندازی PM با قوانین ثابت؛ وضعیت + مرحلهٔ بعد + چه نکنم + پرامپت در صورت نیاز |
| ۲ | seed/تست دیگر دادهٔ روزمره را پاک نکند؛ نمونه فقط اضافه/بدون duplicate؛ پرامپت سازنده |
| ۳ | عوض کردن عکس/قیمت/طرح بدون محتاج بودن به برنامه‌نویس — پنل شبیه وردپرس؟ پلان بده |
| ۴ | اول توصیه کن چی کار کنم؛ وردپرس دو تکه را قبول دارم؛ بعد از OK پرامپت کامل بده |
| ۵ | F را انجام‌شده حساب کن؛ پرامپت فاز ۱ (لندینگ زنده از طرح‌ها) |
| ۶ | در docs ثبت کن: جنریت لوگو/عکس سایت بدون پرسیدن؛ PWA الان یا بعد — ترجیح: بعد از اتمام وب |
| ۷ | تم دارک پیش‌فرض + لایت با سوئیچ شیک در منو؛ در صورت نیاز نسخهٔ light عکس‌ها |
| ۸ | «انجام شد» (تأیید تم) |
| ۹ | خلاصهٔ پرامپت‌های خود صاحب از اول پروژه برای استفادهٔ بعدی — بدون حدس |
| ۱۰ | ثبت همین دفتر در docs (`ثبت`) |
| ۱۱ | ورود چندمسیره: مدیر/منشی رمز؛ مربی/ورزشکار OTP (+رمز پشتیبان)؛ OTP تست `123456`؛ UI موبایل‌اول؛ و هنگام تداخل موبایل کارکنان+ورزشکار صفحهٔ انتخاب نقش (نه اولویت خودکار staff) |
| ۱۲ | آیا مربی باید عضو باشد؟ و آیا مدیر/منشی می‌تواند هم‌زمان مربی باشد؟ → ثبت قانون: مربی≠الزام عضو؛ مدیر+مربی و منشی+مربی روی یک حساب مجاز؛ پرامپت برش J |
| ۱۳ | idle خروج از اکانت: ۵ دقیقه → ۲۵ دقیقه (قفل پرونده عضو همان ۵ بماند) |
| ۱۴ | تأکید دوباره: چت مدیر محصول **هرگز** کد محصول نزند؛ همیشه پرامپت کامل سازنده بدهد حتی اگر صاحب «پرامپت بده» را فراموش کرد؛ فقط با جملهٔ صریح «همین‌جا پیاده کن» مجاز به کد است |
