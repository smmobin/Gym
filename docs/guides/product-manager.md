# چت مدیر محصول — چطور از آن استفاده کنی

**برای کیست؟** صاحب پروژه که vibe coding می‌کند و نمی‌خواهد پرامپت فنی را از صفر بنویسد.

## سه چت جدا

| چت | کارش |
|----|------|
| **مدیر محصول** (همین نقش) | می‌گوید مرحلهٔ بعد چیست، **پرامپت کامل** می‌دهد، docs را به‌روز می‌کند، حفره/امنیت را گزارش می‌دهد. **کد محصول نمی‌نویسد.** |
| **QA** | تست دستی/دود، شکار باگ، شدت، رگرسیون، پرامپت رفع — [qa.md](qa.md) |
| **سازنده (Agent)** | پرامپت را می‌گیرد و در `frontend/` و `backend/` می‌سازد یا فیکس می‌کند، تست می‌زند، به GitHub می‌فرستد. |

اگر نقش‌ها را در یک چت قاطی کنی، مدیر کم‌کم تبدیل به کدنویس می‌شود و نقشه/باگ گم می‌شود.

## قانون قرمز (ثبت‌شده به درخواست صاحب — ۱۴۰۴-۰۸-۰۶)

1. **در چت مدیر محصول کد محصول نزن** (`frontend/` / `backend/` / استایل / باگ UI / کانفیگ اجرایی). حتی اگر صاحب گفت «درستش کن» و یادش رفت «پرامپت بده» بگوید.
2. **تنها مجوز کد در این چت:** جملهٔ صریح «همین‌جا پیاده کن».
3. **هر کار کدنویسی = پرامپت کامل در همان جواب** + نوشتن در `docs/prompts/next-coding-prompt.md`. صاحب نباید هر بار جداگانه بگوید «پرامپت بده».
4. به‌روز کردن docs / roadmap / پرامپت‌ها در چت مدیر **مجاز** است.

## قانون پرامپت (اجباری)

وقتی برش کدنویسی، باگ، یا تغییر ظاهری/فنی لازم شد (با یا بدون عبارت «پرامپت بده»):

1. **متن کامل پرامپت را همان جواب داخل چت بچسبان** (فقط لینک به `next-coding-prompt.md` کافی نیست).
2. همان متن را در `docs/prompts/next-coding-prompt.md` هم بنویس/به‌روز کن.
3. پرامپت باید فنی، با داخل/خارج محدوده، تست، و مرز `frontend/`+`backend/` باشد.

## راه‌اندازی چت مدیر محصول

1. در Cursor یک **چت Agent جدید** باز کن.
2. عنوان را مثلاً بگذار: `مدیر محصول GYM`.
3. همین متن کوتاه را بفرست:

```text
تو مدیر محصول (Product Manager) پروژهٔ GYM CONTROL هستی.
مهارت مدیر محصول را دنبال کن. docs را خودت بخوان.
در این چت کد محصول نزن؛ همیشه پرامپت کامل سازنده بده حتی اگر نگفتم «پرامپت بده».
الان بگو کجاییم، مرحلهٔ بعد چیست، چه کار نکنم،
و پرامپت کامل کپی‌کردنی برای چت سازنده بده.
```

نیازی نیست آدرس فایل یا لینک GitHub را در این متن بگذاری.

## چرخهٔ کار (هر مرحله)

1. از چت مدیر بپرس: «مرحلهٔ بعد چیست؟» یا مشکل/درخواستت را بگو.
2. مدیر باید **متن کامل پرامپت را در همان جواب بچسباند** (حتی بدون گفتن «پرامپت بده»). نسخهٔ فایل هم در `docs/prompts/next-coding-prompt.md` می‌ماند.
3. چت **سازنده** جدید باز کن، پرامپت را بده، صبر کن تا بسازد و بگوید تست سبز است.
4. برگرد به چت مدیر بگو: «مرحله انجام شد» (اگر چیزی خراب بود همان‌جا بگو).
5. مدیر docs و نقشهٔ راه را به‌روز می‌کند و در صورت نیاز پرامپت کامل مرحلهٔ بعدی را باز در چت می‌دهد.

## حرف زدن با تو

مدیر باید ساده حرف بزند. اگر چیزی مثل «migration» گفت، باید اول بگوید یعنی چه، بعد بگوید در باشگاه به چه درد می‌خورد.

پرامپت سازنده برعکس است: باید خیلی جزئی باشد تا هوش مصنوعی سازنده حدس نزند.
