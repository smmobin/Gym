# چت کنترل کیفیت (QA) — چطور از آن استفاده کنی

**برای کیست؟** صاحب پروژه که می‌خواهد باگ و ایراد را منظم پیدا و اولویت‌بندی کند، بدون قاطی شدن با ساخت فیچر.

## سه چت جدا

| چت | کارش |
|----|------|
| **مدیر محصول** | مرحلهٔ بعد، پرامپت برش، نقشهٔ راه، docs وضعیت |
| **QA** (همین نقش) | تست دستی/دود، شکار باگ، شدت، رگرسیون، پرامپت رفع |
| **سازنده (Agent)** | کد فیچر یا فیکس، تست خودکار سبز، commit/push |

اگر QA و سازنده را در یک چت قاطی کنی، گزارش باگ گم می‌شود و دوباره vibe coding بی‌نظم می‌شود.

## راه‌اندازی چت QA

1. در Cursor یک **چت Agent جدید** باز کن.
2. عنوان را مثلاً بگذار: `QA GYM`.
3. پرامپت استارت کامل را از بخش پایین همین فایل (یا از مدیر محصول) کپی و بفرست.

نیازی نیست آدرس فایل یا لینک GitHub را خودت در پرامپت بچسبانی؛ QA باید docs را خودش پیدا کند.

## چرخهٔ کار پیشنهادی

1. بک‌اند `:8000` و فرانت `:5173` را روشن کن (راهنما: [getting-started.md](getting-started.md)).
2. به چت QA بگو: «دور دود کامل» یا «شکار باگ پنل منشی» و غیره.
3. QA باگ‌ها را در [bug-log.md](../qa/bug-log.md) ثبت می‌کند و خلاصه می‌دهد.
4. برای هر Critical/Major مهم: پرامپت رفع را بگیر → چت **سازنده** جدید.
5. بعد از فیکس برگرد به QA بگو: «BUG-00X فیکس شد — رگرسیون بگیر».

## پرامپت استارت چت QA (کپی کامل)

متن زیر را **یک‌جا** در چت Agent جدید بفرست:

```text

هویت و مرز:
- کار تو: تست دستی و دود، شکار باگ، رگرسیون بعد از فیکس، ثبت باگ با شدت، و نوشتن پرامپت رفع برای چت سازنده.

- اولویت roadmap مال مدیر محصول است؛ تو کیفیت و باگ را جلو می‌بری.
- محصول واقعی فقط frontend/ + backend/ با API /api/v1 است. HTML ریشه ماکت GitHub Pages است؛ روی آن باگ محصول واقعی ثبت نکن.

4) باگ‌ها را با شناسه BUG-00X در docs/qa/bug-log.md با قالب استاندارد ثبت/به‌روز کن.

- اگر الان نمی‌توانی UI را ببینی، همان چک‌لیست + نحوهٔ گزارش را آماده کن و بپرس از کدام پنل شروع کنم.
```
