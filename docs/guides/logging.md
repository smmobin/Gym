# سامانهٔ لاگ و فعالیت — GYM CONTROL

**تاریخ:** ۱۴۰۴-۰۸-۲۰ (2026-11-10)  
**وضعیت:** مشخصات محصولی برای برش Logging (پیاده‌سازی در چت سازنده)

## این چیست؟

سه لایهٔ جدا — قاطی نشوند:

| لایه | مخاطب | کجا؟ | چه چیزی؟ |
|------|--------|------|----------|
| **۱) لاگ سیستمی فایل** | فقط سازنده / اپراتور سرور | پوشهٔ محلی `backend/logs/` (در گیت نیست) | تقریباً هر درخواست HTTP، خطا + stack، startup، SMS gateway بدون کلید، … |
| **۲) آدیت دیتابیس** | منبع حقیقت رویدادهای حساس | جدول `audit_logs` (از قبل هست؛ تکمیل می‌شود) | ورود/خروج، پول، عضویت، طرح، تنظیمات، نقش کارکنان، … |
| **۳) پنل مدیر — فعالیت** | مدیر باشگاه در UI | `/manager/#activity` | **زیرمجموعه‌ای خوانا** از آدیت + خلاصهٔ خطاهای مهم — نه کل فایل لاگ |

## چه چیزی در پنل مدیر نیست؟

- محتوای خام `app.log` / `access.log` / `error.log` / `sensitive.log`
- stack trace کامل برای هر خط
- کلید API، رمز عبور، OTP کامل، cookie/session خام
- هر کلیک hash فرانت که به سرور نرسیده (مثلاً فقط عوض شدن `#settings` بدون API)

مدیر باید بفهمد «چه کسی چه کار مهمی کرد» و «خطای مهم سرور کی افتاد» — نه دیباگ تمام‌عیار مثل ترمینال سازنده.

## فایل‌های سازنده (لوکال)

بعد از پیاده‌سازی، مسیر تقریبی روی ویندوز صاحب:

`D:\VibeCoding\Cursor\Gym\backend\logs\`

| فایل | نقش |
|------|-----|
| `access.log` | هر درخواست API/HTTP: method، path، status، مدت پاسخ، request_id، طرح http/https |
| `app.log` | رویدادهای اپلیکیشن + خطاهای عمومی |
| `error.log` | خطاها با جزئیات و stack trace + request_id |
| `sensitive.log` | فقط فیلدهای حساسِ مجاز برای دیباگ (مثلاً موبایل کامل در SMS debug) — **هرگز** رمز، API key، OTP کامل، session token |

همهٔ این پوشه با `.gitignore` (`logs/` و `*.log`) از گیت خارج است.

**آدرس وب برای لاگ کامل سازنده وجود ندارد** (عمدی — تا از اینترنت لو نرود). فقط فایل روی دیسک / سرور.

## Request ID

هر درخواست یک شناسهٔ یکتا می‌گیرد؛ در هدر پاسخ `X-Request-ID` برمی‌گردد و در همهٔ خطوط لاگ همان درخواست تکرار می‌شود تا ردیابی آسان باشد.

## خروجی پنل مدیر

خروجی بازهٔ تاریخ از بخش فعالیت → فایل UTF-8 با پسوند `.log` (نه Excel) — سبک، قابل‌خواندن، بدون دردسر نسخهٔ اکسل.

## قوانین محرمانگی

1. رمز عبور، `SMS_API_KEY`، OTP شش‌رقمی کامل، cookie خام → **هیچ فایلی** (حتی sensitive).
2. در لاگ اصلی: موبایل ماسک (مثلاً `0912***4567`)؛ جزئیات بیشتر فقط در `sensitive.log` اگر برای دیباگ لازم باشد.
3. payload آدیت: قبل/بعد لازم بدون رمز؛ مبالغ و شناسه‌ها OK.
