## باگ‌ها

### BUG-001 — مسیر واگذاری کمد برای عضو بدون طرح شامل‌کمد گیج‌کننده است
- **شدت:** Major
- **نقش / صفحه:** مدیر و منشی → `/manager/#lockers` و `/receptionist/#lockers` (+ ایجاد عضو / تمدید در billing)
- **محیط:** لوکال :8000 (+ :5173 وقتی روشن) | seed | API تأیید شد
- **مراحل تکرار:**
  1. لاگین مدیر `09120000001` / `ChangeMe123`
  2. `#lockers` → کمد آزاد (مثلاً L-03) را انتخاب کن
  3. جستجوی عضو → «علی رضایی» (اشتراک فعال دارد) → واگذاری
  4. مشاهدهٔ پیام: «این عضو عضویت فعال با طرح شامل‌کمد ندارد»
  5. مقایسه: برای «سارا محمدی» (طرح «سه‌ماهه + کمد») واگذاری ممکن است
- **انتظار (از دید میز):** عضو با اشتراک فعال بتواند کمد بگیرد، یا حداقل UI روشن بگوید کدام اعضا/طرح‌ها واجد شرایط‌اند و از ثبت عضو/تمدید بتوان به طرح شامل‌کمد رسید
- **واقعیت:** رفتار سرور مطابق `business-rules.md` §۸ است (اجارهٔ جدا در v1 نیست؛ فقط `includes_locker=true`). علی در seed طرح «ماهانه سالن» (+ بسته مربی) دارد — هیچ‌کدام کمد ندارد. در UI انتخاب طرح/عضویت هنگام واگذاری نیست؛ در فرم عضو جدید هم واگذاری کمد همان‌لحظه نیست؛ در billing هم برچسب «شامل کمد» روی طرح‌ها دیده نمی‌شود
- **شواهد:** `POST /api/v1/lockers/{id}/assign` برای علی → ۴۰۰ با همان متن فارسی؛ فقط طرح id مربوط به «سه‌ماهه + کمد» در seed مقدار `includes_locker=true` دارد
- **احتمال دامنه:** عمدتاً frontend/UX (+ شاید توضیح محصول)؛ منطق backend عمداً سخت‌گیر است
- **وضعیت:** باز

### BUG-002 — داده بعد از قطع/وصل سرور به حالت اول seed برگشت
- **شدت:** — (باگ محصول نیست)
- **نقش / صفحه:** آزادسازی کمد L-01 سارا و تغییرات دیگر
- **محیط:** لوکال Postgres
- **مراحل بررسی QA:**
  1. API: آزادسازی L-01 → `is_free=true` و commit
  2. لاگین مجدد (بدون seed) → وضعیت آزاد مانده بود
  3. ساخت کمد آزمایشی `QA-T-4856` → در لیست ماند
  4. `app.main` lifespan هیچ seed خودکاری ندارد؛ seed فقط با `python -m app.db.seed` و **پاک‌کردن دامنه + پر کردن مجدد** است
- **انتظار:** قطع uvicorn/vite دادهٔ Postgres را عوض نکند
- **واقعیت:** همان‌طور است. برگشت به «سارا روی L-01 و ۵ کمد اولیه» تقریباً فقط بعد از اجرای مجدد seed رخ می‌دهد — نه با صرف ریستارت سرور
- **شواهد:** پس از release بدون seed، L-01 آزاد ماند؛ کمد QA ساخته‌شده در DB ماند
- **احتمال دامنه:** env / عادت توسعه (اجرای seed)
- **وضعیت:** بسته‌شده

### BUG-003 — بعد از ساخت کمد، لیست تا refresh صفحه به‌روز نمی‌شود
- **شدت:** Minor
- **نقش / صفحه:** مدیر/منشی → بخش کمدها → فرم «ساخت کمد»
- **محیط:** گزارش دستی صاحب روی UI؛ API جداگانه تأیید شد
- **مراحل تکرار (گزارش کاربر):**
  1. کد کمد جدید بزن → «ساخت کمد»
  2. همان لحظه ردیف جدید در جدول دیده نمی‌شود
  3. refresh کامل صفحه → کمد ظاهر می‌شود
- **انتظار:** بلافاصله بعد از موفقیت، جدول همان بخش بدون F5 به‌روز شود
- **واقعیت (کد فعلی):** در `frontend/assets/js/lockers.js` بعد از `apiPost` تابع `load()` صداده می‌شود؛ API هم بلافاصله آیتم را در `GET /lockers` برمی‌گرداند. با این حال تست خودکار UI برای این مسیر نیست و Reproduce مرورگر در این دور ممکن نشد (فرانت `:5173` خاموش بود)
- **شواهد:** API create → بلافاصله در list؛ نیاز به تأیید دستی وقتی Vite روشن است
- **احتمال دامنه:** frontend (رندر/کش ماژول/خطای خاموش در `load`) یا محیط (کش مرورگر از باندل قدیمی)
- **وضعیت:** باز
