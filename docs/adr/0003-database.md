# ADR 0003 — دیتابیس

- **وضعیت:** Proposed  
- **تاریخ:** 2026-10-13  
- **مرتبط:** [0002 بک‌اند](0002-backend-stack.md)

## زمینه

داده‌های اصلی سامانه رابطه‌ای‌اند:

- عضو ←→ طرح اشتراک
- عضو ←→ حضورها
- عضو ←→ پرداخت‌ها
- کاربر سیستم ←→ نقش
- گزارش مالی از تراکنش‌های ثبت‌شده

نیاز به یکپارچگی (مثلاً تمدید اشتراک بدون خراب کردن سوابق پرداخت گذشته) و گزارش‌گیری قابل اعتماد داریم.

## تصمیم

| محیط | انتخاب |
|------|--------|
| اصلی (staging / production) | **PostgreSQL 16+** |
| توسعهٔ محلی خیلی سریع (اختیاری) | SQLite فقط برای آزمایش اولیه — قبل از ویژگی‌های جدی به Postgres مهاجرت شود |
| کش (فاز بعد، در صورت نیاز) | Redis — برای صف/نشست؛ نه به‌جای دیتابیس اصلی |

## دلایل

1. **مدل داده رابطه‌ای است** — عضو، پرداخت، حضور، طرح؛ MongoDB اینجا معمولاً پیچیدگی بی‌دلیل می‌آورد.
2. **یکپارچگی و تراکنش** — تمدید + ثبت پرداخت در یک transaction مهم است.
3. **گزارش مالی** — SQL برای جمع درآمد ماهانه، بدهی، فیلتر بازه زمانی طبیعی است.
4. **استاندارد صنعت** — بکاپ، ابزار ادمین، هاستینگ همه‌جا در دسترس است.
5. **هم‌خوان با FastAPI / SQLAlchemy** — مسیر مهاجرت با Alembic روشن است.

## اسکچ موجودیت‌ها (سطح بالا)

هم‌راستا با مدل پروتوتایپ در `docs/product/`:

- `users` / `roles`
- `members`
- `membership_plans`
- `memberships` (سوابق شروع/پایان — جدا از «قیمت طرح فعلی»)
- `attendances`
- `payments`
- `gym_settings`
- بعداً: `audit_logs` برای تغییرات مالی و عضویت

**قاعدهٔ مهم محصول:** تغییر قیمت طرح نباید سوابق پرداخت گذشته را عوض کند. قیمت توافق‌شده در زمان تراکنش/عضویت ذخیره شود.

## عواقب

**مثبت**

- گزارش و صحت داده قابل دفاع
- مسیر رشد تا چند باشگاه / چند شعبه باز می‌ماند

**منفی / هزینه**

- باید بکاپ و نگهداری Postgres را جدی بگیرید
- برای شروع کوچک، کمی بیشتر از «یک فایل JSON» کار دارد — ارزشش را دارد

## جایگزین‌های ردشده (فعلاً)

| گزینه | چرا نه |
|--------|--------|
| فقط LocalStorage / JSON فایل | برای دمو خوب است؛ برای پول و عضویت خطرناک |
| MongoDB به‌عنوان اصلی | رابطه و گزارش مالی را سخت‌تر می‌کند بدون سود واضح |
| MySQL / MariaDB | قابل قبول‌اند؛ Postgres را ترجیح می‌دهیم به‌خاطر JSONB، محدودیت‌ها و اکوسیستم |
| Firebase فقط | قفل فروشنده + مدل دسترسی برای نقش‌های باشگاه معمولاً دردسرساز می‌شود |
