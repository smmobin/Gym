# ADR چیست؟ (Architecture Decision Record)

**ADR** یعنی «ثبت تصمیم معماری»: یک سند کوتاه که می‌گوید *چه چیزی* را انتخاب کردیم، *چرا*، و *چه عواقبی* دارد.

هدف این نیست که کتابچهٔ طولانی بنویسیم. هدف این است که چند ماه بعد (یا وقتی نفر جدید بیاید) بفهمیم:

- چرا React نه Vue؟
- چرا PostgreSQL نه MongoDB؟
- چرا فعلاً اپ اندروید نمی‌سازیم؟

بدون ADR، این‌ها فقط در ذهن افراد می‌ماند و بعداً دوباره بحث و حدس‌زنی شروع می‌شود.

## قالب هر ADR

هر فایل معمولاً این بخش‌ها را دارد:

1. **وضعیت** — Proposed / Accepted / Superseded  
2. **زمینه** — مشکل یا نیاز چیست؟  
3. **تصمیم** — چه چیزی را انتخاب کردیم؟  
4. **دلایل** — چرا این گزینه؟  
5. **عواقب** — چه چیزی ساده‌تر و چه چیزی سخت‌تر می‌شود؟  
6. **جایگزین‌های ردشده** — گزینه‌هایی که دیدیم و نرفتیم سراغشان
