# ADR 0004 — تحویل محصول: سایت اول، سپس PWA

- **وضعیت:** Proposed  
- **تاریخ:** 2026-10-13  
- **مرتبط:** [0001 فرانت](0001-frontend-stack.md)

## زمینه

اولویت فعلی شما:

1. فعلاً **فقط سایت** باشد (وب).
2. شاید بعداً **وب‌اپلیکیشن / PWA**.
3. فعلاً **اپ اندروید بومی نمی‌خواهید**.

پروتوتایپ الان روی GitHub Pages به‌صورت استاتیک قابل دیدن است.

## تصمیم

مسیر فازبندی‌شده:

| فاز | چه می‌سازیم | چه نمی‌سازیم |
|-----|-------------|---------------|
| **۰ — الان** | پروتوتایپ استاتیک + مستندات | بک‌اند واقعی |
| **۱ — سایت عملیاتی** | لندینگ + پنل وب + API + Postgres + ورود واقعی | PWA اجباری، فروشگاه اندروید |
| **۲ — PWA (اختیاری)** | manifest، Service Worker، نصب روی موبایل/دسکتاپ، کش محدود آفلاین برای UI | دسترسی کامل آفلاین به دادهٔ حساس مالی |
| **۳ — بومی** | فقط اگر بعداً نیاز واقعی شد (مثلاً سخت‌افزار خاص یا پلی‌استور) | — |

**تصمیم صریح:** اپ Kotlin/Java/Flutter/React Native در نقشهٔ راه نزدیک **نیست**. موبایل از طریق مرورگر و بعداً PWA پوشش داده می‌شود.

## دلایل

1. **یک کدبیس وب** — منشی پشت میز و ورزشکار روی گوشی، هر دو از همان محصول استفاده می‌کنند.
2. **PWA روی همان React+Vite سوار می‌شود** — نیاز نیست از اول دو پروژه (وب + اندروید) نگه دارید.
3. **هزینه و زمان** — اندروید بومی یعنی امضا، استور، به‌روزرسانی جدا، تست دستگاه؛ برای MVP باشگاه معمولاً زود است.
4. **محدودیت‌های ایران/استور** — مسیر وب+PWA کنترل انتشار را دست خودتان می‌گذارد.
5. **امنیت مالی** — حتی در PWA، عملیات حساس باید آنلاین و سمت سرور بماند؛ آفلاین کامل برای پرداخت/تمدید هدف نیست.

## عواقب

**مثبت**

- تمرکز روی ارزش واقعی: عضویت، حضور، پول، گزارش
- انتشار سریع روی دامنه / GitHub Pages (فرانت) + هاست API
- اگر PWA خواستید، فاز ۲ است نه بازنویسی کامل

**منفی / محدودیت**

- Push notification و برخی قابلیت‌های سخت‌افزاری در PWA محدودتر از اپ بومی است
- روی iOS رفتار PWA محدودیت‌هایی دارد — باید در فاز ۲ تست شود
- «نصب از کافی‌شاپ استور» حس اپ فروشگاهی را دقیقاً نمی‌دهد

## دیپلوی پیشنهادی (سطح بالا)

- **فرانت استاتیک:** GitHub Pages (مثل الان) یا Cloudflare Pages / لیارا  
- **API + DB:** یک VPS یا PaaS با Postgres  
- **HTTPS اجباری** قبل از ورود واقعی و کوکی نشست  

جزئیات استقرار در فاز ۱ داخل `docs/guides/` نوشته می‌شود.
