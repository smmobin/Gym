# ADR 0001 — پشتهٔ فرانت‌اند

- **وضعیت:** Superseded — جایگزین با [0005-frontend-ocean-dark-mpa](0005-frontend-ocean-dark-mpa.md)  
- **تاریخ:** 2026-10-13  
- **مرتبط:** [0004 تحویل و PWA](0004-delivery-and-pwa.md)

## زمینه

الان پروژه یک پروتوتایپ **HTML/CSS/JS خالص** است (لندینگ + سه پنل). برای نسخهٔ واقعی نیاز به:

- کامپوننت‌های قابل استفادهٔ مجدد
- مدیریت state و فرم‌های پیچیده (اعضا، پرداخت، حضور)
- تایپ‌سیف بودن برای مدل‌های Member / Payment / Attendance
- مسیر روشن به سمت **PWA** در آینده (بدون ساخت اپ اندروید بومی)

## تصمیم

برای نسخهٔ عملیاتی:

| لایه | انتخاب |
|------|--------|
| فریمورک UI | **React 19** |
| زبان | **TypeScript** |
| باندلر / ابزار | **Vite** |
| استایل | **CSS Modules** یا Tailwind — ترجیح: سیستم طراحی فعلی Ocean Dark را حفظ کنیم؛ Tailwind فقط اگر سرعت ساخت اولویت شود |
| مسیریابی | React Router |
| PWA (فاز بعد) | `vite-plugin-pwa` |

لندینگ عمومی می‌تواند فعلاً همان HTML استاتیک بماند یا بعداً به همان اپ React ادغام شود.

## دلایل

1. **هم‌راستا با مشخصات اولیهٔ محصول** — خود سند پروتوتایپ React + TypeScript را پیشنهاد کرده بود.
2. **اکوسیستم بزرگ** — کتابخانه، مثال، استخدام و پشتیبانی زیاد.
3. **مسیر PWA ساده** — Vite + Service Worker بدون نیاز به React Native یا Kotlin.
4. **جدا از بک‌اند** — فرانت فقط API مصرف می‌کند؛ می‌توان بک‌اند را جداگانه عوض کرد.
5. **پروتوتایپ فعلی دور ریخته نمی‌شود** — جریان‌ها، کپی‌رایتینگ و تم‌ها مرجع UI می‌مانند؛ فقط پیاده‌سازی به کامپوننت منتقل می‌شود.

## عواقب

**مثبت**

- پنل‌های ورزشکار / منشی / مدیر قابل نگهداری‌تر می‌شوند.
- آماده‌سازی برای نصب روی موبایل به‌صورت PWA راحت‌تر است.
- تایپ‌ها با قرارداد API هم‌خوان می‌مانند.

**منفی / هزینه**

- باید از HTML استاتیک به بیلد Vite مهاجرت کنیم.
- دیپلوی دیگر فقط «آپلود فایل خام» نیست (هرچند خروجی نهایی همچنان استاتیک قابل هاست روی GitHub Pages / Cloudflare / Nginx است).

## جایگزین‌های بررسی‌شده

| گزینه | چرا نه (فعلاً) |
|--------|----------------|
| ادامهٔ HTML خالص | برای پروتوتایپ عالی است؛ برای سامانهٔ واقعی با فرم و نقش زیاد زود شکننده می‌شود. |
| Next.js | عالی اگر SEO لندینگ و SSR خیلی مهم شود؛ برای پنل داخلی باشگاه معمولاً overkill است. بعداً قابل اضافه شدن است. |
| Vue / Svelte | خوب‌اند؛ فقط اکوسیستم/تیم‌فرض ما و سند اولیه به React نزدیک‌تر است. |
| React Native / Flutter | برای اپ بومی‌اند؛ شما فعلاً اندروید بومی نمی‌خواهید. |
