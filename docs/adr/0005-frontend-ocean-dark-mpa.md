# ADR 0005 — فرانت عملیاتی Ocean Dark (MPA بدون React)

- **وضعیت:** Accepted  
- **تاریخ:** 2026-10-19  
- **جایگزین می‌کند:** [0001-frontend-stack](0001-frontend-stack.md)  
- **مرتبط:** [0004 تحویل و PWA](0004-delivery-and-pwa.md)

## زمینه

ADR 0001 فرانت عملیاتی را React + TypeScript + Vite انتخاب کرده بود. اسکلت React با صفحات مینیمال به همهٔ APIهای `/api/v1` وصل شد، ولی صاحب پروژه صریحاً تصمیم گرفت UI محصول همان ظاهر و جریان **پروتوتایپ Ocean Dark** باشد — نه صفحات سادهٔ React.

نگه داشتن دو UI موازی (React موقت + ماکت HTML) منبع حقیقت را دوگانه می‌کند و باگ‌های پروتوتایپ دیده نمی‌شوند.

## تصمیم

| لایه | انتخاب |
|------|--------|
| UI | **Multi-page HTML + CSS + JS وانیلا** داخل `frontend/` |
| تم | Ocean Dark پیش‌فرض + تم روشن اختیاری کاربر (`data-theme` / `localStorage`)؛ Vazirmatn / RTL |
| ابزار بیلد | **Vite** بدون پلاگین React — خروجی استاتیک |
| ارتباط با API | `fetch` با `credentials: 'include'`؛ پروکسی `/api` → بک‌اند |
| React | **حذف از محصول** |

صفحات اصلی: لندینگ، ورود یکپارچه (`/login/`)، پنل منشی، پنل مدیر، پنل مربی (`/trainer/`)، داشبورد ورزشکار.

## دلایل

1. **تصمیم محصولی صاحب:** ظاهر پروتوتایپ = UI اصلی.
2. **یک منبع حقیقت UI:** همان تم به API واقعی وصل است.
3. **سبک‌تر از React** برای پنل داخلی باشگاه در این مرحله.
4. خروجی همچنان استاتیک و قابل دیپلوی است (PWA بعداً طبق ADR 0004 قابل افزودن است).

## عواقب

**مثبت**

- parity بصری با چیزی که روی GitHub Pages دیده می‌شد.
- حذف وابستگی‌های React از محصول.

**منفی / هزینه**

- فرم‌های پیچیده بدون کامپوننت‌فریم‌ورک؛ ماژول‌های JS باید منظم بمانند.
- GitHub Pages ریشه همچنان بدون بک‌اند است — لاگین واقعی فقط با API.

## جایگزین‌های بررسی‌شده

| گزینه | چرا نه |
|--------|--------|
| ادامه React + پوسته‌سازی شبیه Ocean Dark | رد شد توسط صاحب؛ اسکلت مینیمال قابل قبول نبود. |
| دو UI موازی برای مقایسه | ممنوع — یکی باید بماند. |
| فقط HTML ریشه بدون Vite | پروکسی/بیلد/تست و مسیرهای تمیز سخت‌تر می‌شود. |
