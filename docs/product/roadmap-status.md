# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش غیبت کلاس تأیید شد  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

کارکنان: اعضا، حضور، مالی، کلاس (+ غیبت/حاضر و مصرف جلسه)، کمد، مربی/برنامه.  
هنوز باز: قفل پرونده، گزارش مدیر، مهمان/آزمایشی، تنظیمات، پنل ورزشکار.

## انجام شده

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- auth + `/login`
- اعضا + `/members`
- حضور + `/attendance`
- مالی + `/billing`
- کلاس + رزرو + **no-show / attended** + `/classes`
- کمد + `/lockers`
- مربی/برنامه + `/trainers` + `/workouts`

## الان نکن

- لاگین ورزشکار، پیامک واقعی، درگاه آنلاین واقعی
- HTML ریشه به‌عنوان محصول واقعی
- کرون خودکار علامت‌گذاری همهٔ غایب‌ها (دستی توسط منشی کافی است)
- ساخت هم‌زمان قفل پرونده + گزارش مدیر + مهمان

## مرحلهٔ بعد (همین حالا)

**یک جمله:** قفل پروندهٔ ۵دقیقه‌ای هنگام ویرایش حساس عضو.

| به زبان ساده | یعنی چه |
|--------------|---------|
| قفل | یک نفر پرونده را باز کرده؛ دیگری هشدار می‌بیند |
| مدت | حدود ۵ دقیقه |
| هدف | جلوگیری از تداخل منشی‌ها روی تمدید/پرداخت |

پرامپت کامل: [next-coding-prompt.md](../prompts/next-coding-prompt.md)

## بعد از آن (صف)

1. گزارش هزینه/سود مدیر
2. فرم آزمایشی عمومی → صف منشی؛ مهمان روزانه
3. تنظیمات باشگاه؛ اعلان داخل‌برنامه؛ placeholder پیامک/درگاه
4. پنل ورزشکار وقتی کارکنان پایدار شد
5. HTTPS و بکاپ قبل از دادهٔ واقعی
