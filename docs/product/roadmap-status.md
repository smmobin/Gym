# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۵ (2026-10-17) — مدیر محصول تأیید کرد: auth کارکنان انجام شد  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

انبار داده + ورود واقعی کارکنان آماده‌اند (cookie نشست HttpOnly، نقش سمت سرور، صفحهٔ `/login`).  
**هنوز نیست:** API/UI ثبت و لیست عضو، حضور، پرداخت عملیاتی.

## انجام شده

- پروتوتایپ UI و تم Ocean Dark (GitHub Pages)
- اسکلت `frontend/` / `backend/` + تست health
- قوانین پروژه، امنیت، ADR، قوانین کسب‌وکار
- مدل‌ها / migration / seed ساختگی
- **auth کارکنان:** login / logout / me / staff-ping / تغییر رمز مدیر + `staff_sessions` + bcrypt
- صفحهٔ ورود React + تست‌های مرتبط (pytest سبز تأیید شد)

## الان نکن

- لاگین ورزشکار / پنل ورزشکار
- حضور، تمدید، پرداخت، کلاس، کمد (بعد از برش عضو)
- پیامک واقعی / درگاه آنلاین واقعی
- دادهٔ واقعی عضو در گیت یا seed
- دست زدن به HTML ریشه به‌عنوان محصول واقعی
- پنل کامل همهٔ نقش‌ها در یک برش

## مرحلهٔ بعد (همین حالا)

**یک جمله:** برش عمودی «لیست + ثبت عضو» با API محافظت‌شده و حداقل UI پشت لاگین کارکنان.

| چیست به زبان ساده | یعنی چه |
|-------------------|---------|
| برش عمودی | از دیتابیس تا API تا یک صفحهٔ ساده — یک جریان کامل |
| لیست/ثبت عضو | منشی/مدیر عضو ببینند و عضو جدید ثبت کنند |
