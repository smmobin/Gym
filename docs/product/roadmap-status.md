# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش گزارش هزینه/سود مدیر انجام شد؛ مرحلهٔ بعد مهمان/آزمایشی  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

کارکنان پایدار: اعضا، حضور، مالی میز، کلاس، کمد، مربی، قفل پرونده، **گزارش هزینه/سود مدیر**.  
هنوز باز: مهمان/آزمایشی، تنظیمات، اعلان، پنل ورزشکار.

## انجام شده

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- auth + `/login`
- اعضا + `/members`
- حضور + `/attendance`
- مالی میز + `/billing`
- کلاس + no-show/attended + `/classes`
- کمد + `/lockers`
- مربی/برنامه + `/trainers` + `/workouts`
- قفل پرونده ۵دقیقه‌ای + UI در `/billing` و `/attendance`
- گزارش مدیر: `GET/POST /expenses` + `GET /reports/profit` + UI `/reports`

## الان نکن

- لاگین ورزشکار، پیامک واقعی، درگاه آنلاین واقعی
- HTML ریشه به‌عنوان محصول واقعی
- دادن گزارش سود به منشی
- حسابداری پیچیده / فاکتور خرید / مالیات
- ساخت هم‌زمان تنظیمات + اعلان در همین برش بعدی

## مرحلهٔ بعد (همین حالا)

**یک جمله:** فرم آزمایشی عمومی → صف منشی؛ مهمان روزانه.

| به زبان ساده | یعنی چه |
|--------------|---------|
| فرم سایت | درخواست واقعی در صف منشی |
| مهمان | عضو موقت ۱روزه + پرداخت |
| نقش | desk می‌سازد |

## بعد از آن (صف)

1. تنظیمات باشگاه؛ اعلان داخل‌برنامه؛ placeholder پیامک/درگاه
2. پنل ورزشکار وقتی کارکنان پایدار شد
3. HTTPS و بکاپ قبل از دادهٔ واقعی

## حفره‌ها

- قفل روی UI ویرایش اعضا هنوز نیست (سرور PATCH را enforce می‌کند)
- ویرایش/حذف هزینه در گزارش مدیر عمداً نیست (v1 فقط ایجاد+لیست)
