# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش قفل پرونده تأیید شد؛ مرحلهٔ بعد گزارش مدیر  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

کارکنان پایدار: اعضا، حضور، مالی میز، کلاس، کمد، مربی، **قفل پرونده**.  
هنوز باز: **گزارش هزینه/سود مدیر**، مهمان/آزمایشی، تنظیمات، اعلان، پنل ورزشکار.

## انجام شده

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- auth + `/login`
- اعضا + `/members`
- حضور + `/attendance`
- مالی میز + `/billing`
- کلاس + no-show/attended + `/classes`
- کمد + `/lockers`
- مربی/برنامه + `/trainers` + `/workouts`
- قفل پرونده ۵دقیقه‌ای + UI در `/billing` و `/attendance`

## الان نکن

- لاگین ورزشکار، پیامک واقعی، درگاه آنلاین واقعی
- HTML ریشه به‌عنوان محصول واقعی
- دادن گزارش سود به منشی
- حسابداری پیچیده / فاکتور خرید / مالیات در همین برش
- ساخت هم‌زمان مهمان + تنظیمات + اعلان در همین برش

## مرحلهٔ بعد (همین حالا)

**یک جمله:** گزارش هزینه و سود نمایشی فقط برای مدیر.

| به زبان ساده | یعنی چه |
|--------------|---------|
| هزینه | دسته + تاریخ + مبلغ |
| درآمد | فقط پرداخت‌های `paid` |
| سود | درآمد − هزینه |
| UI | `/reports` یا مشابه؛ فقط manager |

## بعد از آن (صف)

1. فرم آزمایشی عمومی → صف منشی؛ مهمان روزانه
2. تنظیمات باشگاه؛ اعلان داخل‌برنامه؛ placeholder پیامک/درگاه
3. پنل ورزشکار وقتی کارکنان پایدار شد
4. HTTPS و بکاپ قبل از دادهٔ واقعی
