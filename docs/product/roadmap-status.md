# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش کمد تأیید شد؛ مرحلهٔ بعد مربی/برنامه  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

Auth + اعضا + حضور + مالی + کلاس + **کمد** آماده‌اند (`/lockers`).  
مدل واگذاری مربی و برنامه تمرینی در seed هست، ولی **API/UI پنل مربی هنوز نیست**.

## انجام شده

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- auth کارکنان + `/login`
- اعضا + `/members`
- حضور + `/attendance`
- مالی + `/billing`
- کلاس گروهی + `/classes`
- کمد واگذاری/آزادسازی + `/lockers`

## الان نکن

- لاگین ورزشکار، پیامک واقعی، درگاه آنلاین واقعی
- HTML ریشه به‌عنوان محصول واقعی
- ادیتور ورزشی پیچیده / ویدیو / PDF
- ساخت هم‌زمان گزارش مدیر + قفل پرونده + مهمان در همین برش

## مرحلهٔ بعد (همین حالا)

**یک جمله:** واگذاری مربی ↔ شاگرد + برنامه تمرینی متنی ساده.

| به زبان ساده | یعنی چه |
|--------------|---------|
| واگذاری | desk عضو را به مربی وصل/قطع می‌کند |
| برنامه | مربی برای شاگرد خودش می‌نویسد؛ مدیر همه |
| چند مربی | هم‌زمان برای یک شاگرد مجاز |
| UI | صفحه(های) ساده پشت لاگین |

پرامپت کامل: [next-coding-prompt.md](../prompts/next-coding-prompt.md)

## بعد از آن (صف)

1. مصرف جلسه برای غیبت کلاس
2. قفل پروندهٔ ۵دقیقه‌ای
3. گزارش هزینه/سود مدیر
4. فرم آزمایشی عمومی → صف منشی؛ مهمان روزانه
5. تنظیمات باشگاه؛ اعلان داخل‌برنامه؛ placeholder پیامک/درگاه
6. پنل ورزشکار وقتی کارکنان پایدار شد
7. HTTPS و بکاپ قبل از دادهٔ واقعی
