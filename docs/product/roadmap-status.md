# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۳ (2026-10-15)  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

اسکلت آماده است: پروتوتایپ HTML برای دمو، React و FastAPI خالیِ سلامت سیستم، Postgres محلی `gym_control`.  
قوانین باشگاه با صاحب پروژه بسته شده و در `business-rules.md` است.

**هنوز ساخته نشده:** جدول‌های واقعی، seed، ورود کارکنان، پنل‌ها، کلاس، کمد، پول واقعی.

## انجام شده

- پروتوتایپ UI و تم Ocean Dark (GitHub Pages)
- اسکلت `frontend/` و `backend/` + تست health
- قوانین پروژه، امنیت، ADR پشته
- قوانین کسب‌وکار محصول (نقش، پول، حضور، کلاس، …)

## الان نکن

- لاگین واقعی و پنل React کامل (قبل از مدل و seed)
- پیامک واقعی / درگاه آنلاین واقعی
- دادهٔ واقعی عضو در گیت یا seed
- جدا کردن ریپو یا Docker کامل مگر مرحلهٔ جدا و تأییدشده (اولویت الان مدل داده است)
- دست زدن به HTML ریشه به‌عنوان محصول واقعی

## مرحلهٔ بعد (همین حالا)

**یک جمله:** شکل قفسه‌های انبار را در دیتابیس بساز (جدول‌ها) + نسخهٔ کنترل‌شدهٔ این شکل (migration) + دادهٔ ساختگی تا سیستم خالی نباشد (seed).

| چیست به زبان ساده | یعنی چه |
|-------------------|--------|
| مدل | نقشهٔ جدول‌ها: عضو، طرح، اشتراک، حضور، پرداخت، … |
| migration | دستور قابل تکرار برای ساخت همان جدول‌ها در Postgres |
| seed | اعضای ساختگی مثل علی رضایی تا داشبورد بعدی خالی نباشد |

پرامپت کامل برای چت **سازنده:** [next-coding-prompt.md](../prompts/next-coding-prompt.md)
