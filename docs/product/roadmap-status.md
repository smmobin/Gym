# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش قفل پرونده تأیید/پیاده‌سازی شد؛ مرحلهٔ بعد گزارش مدیر  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

کارکنان: اعضا، حضور، مالی، کلاس، کمد، مربی/برنامه، **قفل پروندهٔ ۵دقیقه‌ای**.  
هنوز باز: گزارش مدیر، مهمان/آزمایشی، تنظیمات، پنل ورزشکار.

## انجام شده

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- auth + `/login`
- اعضا + `/members`
- حضور + `/attendance`
- مالی + `/billing`
- کلاس + رزرو + no-show/attended + `/classes`
- کمد + `/lockers`
- مربی/برنامه + `/trainers` + `/workouts`
- قفل پرونده (`member_file_locks`) + UI `/billing` و `/attendance`

## الان نکن

- لاگین ورزشکار، پیامک واقعی، درگاه آنلاین واقعی
- HTML ریشه به‌عنوان محصول واقعی
- Redis/WebSocket اجباری برای قفل (Postgres کافی است)
- ساخت هم‌زمان گزارش مدیر + مهمان + تنظیمات در همین برش

## مرحلهٔ بعد (همین حالا)

**یک جمله:** گزارش هزینه/سود ساده برای مدیر.

| به زبان ساده | یعنی چه |
|--------------|---------|
| هزینه | دسته + تاریخ + مبلغ |
| سود نمایشی | درآمد پرداخت‌شده − هزینه‌ها |
| نقش | فقط مدیر |

## بعد از آن (صف)

1. فرم آزمایشی عمومی → صف منشی؛ مهمان روزانه
2. تنظیمات باشگاه؛ اعلان داخل‌برنامه؛ placeholder پیامک/درگاه
3. پنل ورزشکار وقتی کارکنان پایدار شد
4. HTTPS و بکاپ قبل از دادهٔ واقعی

## حفره‌ها

- گزارش مالی مدیر — جدول expense هست؛ UI بعداً
- قفل روی ویرایش UI اعضا هنوز نیست (سرور PATCH را enforce می‌کند؛ UI قفل در billing/attendance)
