# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش استقرار/بکاپ در docs+اسکریپت  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

**نسخهٔ عملیاتی روی لوکال برای کارکنان + ورزشکار آماده است.**  
راهنما و اسکریپت استقرار/بکاپ در ریپو هست؛ **دیپلوی واقعی روی اکانت هاست صاحب** هنوز کار دستی اوست (رمز در گیت نیست).

## انجام شده (محصول)

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- کارکنان: auth، اعضا، حضور، مالی، کلاس، کمد، مربی/برنامه، قفل پرونده، گزارش، آزمایشی/مهمان، تنظیمات، اعلان، placeholder پیامک
- ورزشکار: `/athlete/login` + داشبورد خود + درخواست تمدید → اعلان desk
- استقرار: `docs/guides/deploy.md` + `backup.md`؛ اسکریپت `backup_db` / `restore_db`؛ `.env.example` کامل؛ Docker/compose اختیاری؛ seed در prod مسدود

## الان نکن

- وارد کردن دادهٔ واقعی عضو قبل از HTTPS + بکاپ + یک‌بار restore
- پیامک/درگاه واقعی بدون طراحی جدا
- seed پاک‌کننده روی دیتابیس production
- فرض کردن GitHub Pages به‌عنوان سامانهٔ واقعی

## مرحلهٔ بعد (همین حالا)

**یک جمله:** صاحب پروژه طبق deploy.md هاست بگیرد، env را ست کند، یک‌بار restore تمرین کند؛ سپس دادهٔ واقعی.

## بعد از آن (صف اختیاری محصول)

1. freeze عضویت (در قوانین هست؛ API/UI هنوز نه)
2. رزرو کلاس توسط ورزشکار
3. اتصال واقعی پیامک / درگاه

## حفره‌ها

- GitHub Pages ≠ محصول واقعی
- freeze عضویت — باز
- دیپلوی روی اکانت واقعی — دستی صاحب (عمداً در گیت نیست)
