# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش گزارش مدیر تأیید شد؛ مرحلهٔ بعد مهمان/آزمایشی  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

محصول واقعی (React + FastAPI + Postgres) روی **لوکال** جلو رفته؛ گزارش مدیر `/reports` هم هست.  
سایت GitHub Pages هنوز **فقط ماکت HTML** است — لاگین/دیتابیس واقعی ندارد.

## انجام شده

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- auth، اعضا، حضور، مالی میز، کلاس، کمد، مربی/برنامه، قفل پرونده
- گزارش هزینه/سود مدیر + `/reports`

## الان نکن

- انتظار دیدن بک‌اند واقعی روی `*.github.io`
- لاگین ورزشکار، پیامک واقعی، درگاه آنلاین واقعی
- وصل کردن HTML ریشه به API به‌عنوان محصول نهایی
- ساخت هم‌زمان تنظیمات + اعلان در همین برش

## مرحلهٔ بعد (همین حالا)

**یک جمله:** فرم آزمایشی عمومی → صف منشی + ثبت مهمان روزانه.

| به زبان ساده | یعنی چه |
|--------------|---------|
| `/trial` | فرم بدون لاگین → `trial_leads` |
| صف | منشی وضعیت را عوض می‌کند؛ عضو خودکار ساخته نمی‌شود |
| مهمان | عضو + اشتراک ۱روزه (+ پرداخت) |
| UI | React در `frontend/` |

## بعد از آن (صف)

1. تنظیمات باشگاه؛ اعلان داخل‌برنامه؛ placeholder پیامک/درگاه
2. پنل ورزشکار وقتی کارکنان پایدار شد

## حفره‌ها

- GitHub Pages ≠ محصول واقعی
- قفل روی UI ویرایش اعضا هنوز نیست
- ویرایش/حذف هزینه در گزارش مدیر عمداً نیست
