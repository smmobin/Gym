# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۴ (2026-10-16) — پس از برش auth کارکنان  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

مدل/migration/seed آماده‌اند و **ورود واقعی کارکنان** با cookie نشست HttpOnly، نقش سمت سرور، و صفحهٔ `/login` در React پیاده شده است.  
**هنوز نیست:** CRUD اعضا و پنل‌های عملیاتی منشی/مدیر/مربی.

## انجام شده

- پروتوتایپ UI و تم Ocean Dark (GitHub Pages)
- اسکلت `frontend/` و `backend/` + تست health
- قوانین پروژه، امنیت، ADR، قوانین کسب‌وکار
- مدل‌ها / جدول‌های v1 + migration اولیه + seed
- **auth کارکنان:** login / logout / me / staff-ping / تغییر رمز توسط مدیر + جدول `staff_sessions`
- صفحهٔ ورود React (فارسی/RTL) + تست‌های pytest/vitest مرتبط

## الان نکن

- لاگین ورزشکار / پنل ورزشکار
- پنل کامل اعضا/حضور/پرداخت قبل از برش عضو
- پیامک واقعی / درگاه آنلاین واقعی
- دادهٔ واقعی عضو در گیت یا seed
- دست زدن به HTML ریشه به‌عنوان محصول واقعی

## مرحلهٔ بعد (همین حالا)

**یک جمله:** برش عمودی «لیست/ثبت عضو» با API محافظت‌شده + حداقل UI پشت لاگین کارکنان.

## بعد از آن (صف، نه همزمان)

1. حضور ورود/خروج
2. تمدید + پرداخت + audit
3. کلاس / کمد / مربی به‌ترتیب ارزش روزانه
4. پنل ورزشکار وقتی کارکنان پایدار شد
5. HTTPS و بکاپ قبل از دادهٔ واقعی باشگاه
