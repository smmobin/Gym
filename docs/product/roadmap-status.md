# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش مربی/برنامه تأیید شد  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

Auth + اعضا + حضور + مالی + کلاس + کمد + **واگذاری مربی و برنامه تمرینی** آماده‌اند (`/trainers`, `/workouts`).

## انجام شده

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- auth کارکنان + `/login`
- اعضا + `/members`
- حضور + `/attendance`
- مالی + `/billing`
- کلاس گروهی + `/classes`
- کمد واگذاری/آزادسازی + `/lockers`
- واگذاری مربی ↔ شاگرد + برنامه متنی + `/trainers` + `/workouts`

## الان نکن

- لاگین ورزشکار، پیامک واقعی، درگاه آنلاین واقعی
- HTML ریشه به‌عنوان محصول واقعی
- ادیتور ورزشی پیچیده / ویدیو / PDF
- ساخت هم‌زمان گزارش مدیر + قفل پرونده + مهمان در همین برش

## مرحلهٔ بعد (همین حالا)

**یک جمله:** مصرف جلسه برای غیبت در کلاس رزروشده (هم‌راستا با حضور).

| به زبان ساده | یعنی چه |
|--------------|---------|
| غیبت کلاس | اگر عضو در کلاس رزروشده حاضر نشود، یک جلسه از بستهٔ class کم شود |
| ابهام بسته | اگر بستهٔ منطبق نبود، منشی با هشدار انتخاب کند |
| خارج از برش | قفل پرونده، گزارش سود، فرم آزمایشی |

پرامپت کامل: [next-coding-prompt.md](../prompts/next-coding-prompt.md)

## بعد از آن (صف)

1. قفل پروندهٔ ۵دقیقه‌ای
2. گزارش هزینه/سود مدیر
3. فرم آزمایشی عمومی → صف منشی؛ مهمان روزانه
4. تنظیمات باشگاه؛ اعلان داخل‌برنامه؛ placeholder پیامک/درگاه
5. پنل ورزشکار وقتی کارکنان پایدار شد
6. HTTPS و بکاپ قبل از دادهٔ واقعی
