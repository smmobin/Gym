# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش تنظیمات/اعلان تأیید شد؛ مرحلهٔ بعد پنل ورزشکار  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

**کارکنان پایدار است** (اعضا تا تنظیمات و اعلان و placeholder پیامک).  
مرحلهٔ بعد طبق صف: **پنل ورزشکار**. بعد از آن تمرکز روی دیپلوی واقعی (HTTPS + بکاپ).

## انجام شده

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- auth کارکنان، اعضا، حضور، مالی میز، کلاس، کمد، مربی/برنامه، قفل پرونده
- گزارش مدیر `/reports`
- آزمایشی `/trial` + صف + مهمان `/guests`
- تنظیمات `/settings` + اعلان زنگوله + `/sms-templates` (دکمهٔ مرده)

## الان نکن

- پیامک واقعی / OTP پیامکی / درگاه آنلاین واقعی
- HTML ریشه به‌عنوان محصول واقعی
- رزرو کلاس توسط ورزشکار در همین برش (مگر سازنده خیلی ارزان بسازد — پیش‌فرض خارج است)
- خرید SDK و گذاشتن کلید در گیت

## مرحلهٔ بعد (همین حالا)

**یک جمله:** لاگین ورزشکار با موبایل+رمز و دیدن فقط دادهٔ خودش + درخواست تمدید به‌صورت اعلان.

| به زبان ساده | یعنی چه |
|--------------|---------|
| ورود | `/athlete/login` — cookie جدا از کارکنان |
| داده | عضویت، بدهی، پرداخت، برنامه (خواندن) |
| تمدید | درخواست → اعلان desk؛ بدون درگاه |
| رمز | desk ست می‌کند (پیامک نداریم) |

پرامپت کامل: [next-coding-prompt.md](../prompts/next-coding-prompt.md)

## بعد از آن (صف)

1. آماده‌سازی استقرار: هاست واقعی (مثلاً لیارا)، HTTPS، بکاپ Postgres + تست restore
2. قفل روی UI ویرایش اعضا (حفرهٔ کوچک)
3. اختیاری بعدی: رزرو کلاس توسط ورزشکار، اتصال واقعی پیامک/درگاه

## حفره‌ها

- GitHub Pages ≠ محصول واقعی
- قفل روی UI ویرایش اعضا هنوز نیست
- درخواست تمدید واقعی منتظر لاگین ورزشکار بود — **همین برش**
