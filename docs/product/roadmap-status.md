# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش کمد تأیید/انجام شد  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

Auth + اعضا + حضور + مالی + کلاس گروهی + **کمد (واگذاری/آزادسازی)** آماده‌اند (`/lockers`).

## انجام شده

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- auth کارکنان + صفحهٔ `/login`
- اعضا: لیست/ثبت/آرشیو + `/members`
- حضور: check-in/out + `/attendance`
- مالی: طرح‌ها، تمدید، پرداخت ناقص، refund، رسید `R-…`، audit + `/billing`
- کلاس گروهی: لیست/ساخت/ویرایش، رزرو/لغو، ظرفیت، هشدار تداخل مربی + `/classes`
- کمد: لیست/ساخت، واگذاری فقط با `includes_locker`، آزادسازی + `/lockers`

## الان نکن

- لاگین ورزشکار، پیامک واقعی، درگاه آنلاین واقعی
- HTML ریشه به‌عنوان محصول واقعی
- اجارهٔ ماهانهٔ جدا برای کمد
- ساخت هم‌زمان پنل مربی کامل + گزارش مدیر + قفل پرونده در یک برش

## مرحلهٔ بعد (همین حالا)

**یک جمله:** واگذاری مربی + برنامه تمرینی ساده برای شاگردهای مربی.

| به زبان ساده | یعنی چه |
|--------------|---------|
| واگذاری شاگرد | مدیر/منشی عضو را به مربی وصل می‌کند |
| برنامه | مربی برای شاگرد خودش می‌نویسد |
| دسترسی | مربی فقط شاگردهای خودش |
| UI | صفحهٔ ساده پشت لاگین |

## بعد از آن (صف)

1. مصرف جلسه برای غیبت کلاس (با حضور/بستهٔ class)
2. قفل پروندهٔ ۵دقیقه‌ای
3. گزارش هزینه/سود مدیر (جدول `expenses` هست)
4. فرم آزمایشی عمومی → صف منشی؛ مهمان روزانه
5. تنظیمات باشگاه؛ اعلان داخل‌برنامه؛ placeholder پیامک/درگاه
6. پنل ورزشکار وقتی کارکنان پایدار شد
7. HTTPS و بکاپ قبل از دادهٔ واقعی
