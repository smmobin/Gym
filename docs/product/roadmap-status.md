# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش مربی تأیید شد؛ مرحلهٔ بعد غیبت کلاس  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

کارکنان پایدارتر شده‌اند: اعضا، حضور، مالی، کلاس، کمد، **واگذاری مربی و برنامه** (`/trainers`, `/workouts`).  
هنوز باز: مصرف جلسه برای غیبت کلاس، قفل پرونده، گزارش مدیر، مهمان/آزمایشی، تنظیمات، پنل ورزشکار.

## انجام شده

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- auth + `/login`
- اعضا + `/members`
- حضور + `/attendance`
- مالی + `/billing`
- کلاس + `/classes`
- کمد + `/lockers`
- مربی/برنامه + `/trainers` + `/workouts`

## الان نکن

- لاگین ورزشکار، پیامک واقعی، درگاه آنلاین واقعی
- HTML ریشه به‌عنوان محصول واقعی
- کرون پیچیدهٔ علامت‌گذاری خودکار همهٔ غایب‌ها (مگر خیلی ارزان)
- قفل پرونده + گزارش مدیر هم‌زمان در همین برش

## مرحلهٔ بعد (همین حالا)

**یک جمله:** ثبت غیبت روی رزرو کلاس → کم شدن یک جلسه از بستهٔ class.

| به زبان ساده | یعنی چه |
|--------------|---------|
| no_show | رزرو از booked خارج؛ ظرفیت آزاد |
| مصرف جلسه | `sessions_remaining` یک واحد کم |
| ابهام | منشی با هشدار `membership_id` می‌دهد |
| UI | دکمه روی رزروهای `/classes` |

پرامپت کامل: [next-coding-prompt.md](../prompts/next-coding-prompt.md)

## بعد از آن (صف)

1. قفل پروندهٔ ۵دقیقه‌ای
2. گزارش هزینه/سود مدیر
3. فرم آزمایشی عمومی → صف منشی؛ مهمان روزانه
4. تنظیمات باشگاه؛ اعلان داخل‌برنامه؛ placeholder پیامک/درگاه
5. پنل ورزشکار وقتی کارکنان پایدار شد
6. HTTPS و بکاپ قبل از دادهٔ واقعی
