# وضعیت نقشهٔ راه — GYM CONTROL

**آخرین به‌روزرسانی:** ۱۴۰۴-۰۷-۲۷ (2026-10-19) — برش کلاس تأیید شد؛ مرحلهٔ بعد کمد  
**نقش:** سند زندهٔ مدیر محصول — بعد از هر مرحلهٔ انجام‌شده باید عوض شود.

## الان کجاییم؟

Auth + اعضا + حضور + مالی + کلاس گروهی/رزرو آماده‌اند (`/classes`).  
مدل و seed کمد هست، ولی **API/UI واگذاری کمد هنوز نیست**.

## انجام شده

- اسکلت، مدل‌ها، migration، seed، قوانین کسب‌وکار
- auth کارکنان + صفحهٔ `/login`
- اعضا: لیست/ثبت/آرشیو + `/members`
- حضور: check-in/out + `/attendance`
- مالی: طرح‌ها، تمدید، پرداخت ناقص، refund، رسید `R-…`، audit + `/billing`
- کلاس گروهی: لیست/ساخت/ویرایش، رزرو/لغو، ظرفیت، هشدار تداخل مربی + `/classes`

## الان نکن

- لاگین ورزشکار، پیامک واقعی، درگاه آنلاین واقعی
- HTML ریشه به‌عنوان محصول واقعی
- ساخت هم‌زمان پنل مربی + گزارش مدیر + قفل پرونده در همین برش
- اجارهٔ ماهانهٔ جدا برای کمد (v1 فقط با طرح شامل‌کمد)

## مرحلهٔ بعد (همین حالا)

**یک جمله:** کمد — واگذاری و آزادسازی برای اعضایی که طرح شامل‌کمد دارند.

| به زبان ساده | یعنی چه |
|--------------|---------|
| لیست کمدها | آزاد / اشغال + عضو فعلی |
| واگذاری | فقط با عضویت/`includes_locker` |
| آزادسازی | `released_at` و آزاد شدن جا |
| UI | `/lockers` پشت لاگین |

پرامپت کامل: [next-coding-prompt.md](../prompts/next-coding-prompt.md)

## بعد از آن (صف)

1. واگذاری مربی + برنامه تمرینی (پنل مربی)
2. مصرف جلسه برای غیبت کلاس (با حضور/بستهٔ class)
3. قفل پروندهٔ ۵دقیقه‌ای
4. گزارش هزینه/سود مدیر (جدول `expenses` هست)
5. فرم آزمایشی عمومی → صف منشی؛ مهمان روزانه
6. تنظیمات باشگاه؛ اعلان داخل‌برنامه؛ placeholder پیامک/درگاه
7. پنل ورزشکار وقتی کارکنان پایدار شد
8. HTTPS و بکاپ قبل از دادهٔ واقعی

## حفره‌ها

- قفل پروندهٔ ۵دقیقه‌ای — هنوز باز است ([schema-todos.md](schema-todos.md))
- مصرف جلسه برای غیبت کلاس — عمداً در برش کلاس نیامد
- هزینهٔ باشگاه / سود مدیر: جدول هست؛ UI گزارش کامل بعداً
- API کمد/مربی کامل هنوز نیامده (مدل + seed هست)
